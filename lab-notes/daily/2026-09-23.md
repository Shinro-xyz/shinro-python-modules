# 2026-09-23 — Recurrent-policy support: fused LSTM/GRU/RNN cell kernels

Branch: `feat/nn-kernel-support`

## Why

The ONNX importer can already lower memoryless policies (Gemm/Elu MLPs). The next
class of real robotics policies carries recurrence — an LSTM/GRU/RNN cell whose
hidden state must be fed back each tick. Two earlier findings framed the work:

1. A full HF survey (see below) showed recurrent robot policies *do* exist and are
   importable in principle, but they are rare; the ecosystem is overwhelmingly MLP.
2. The recurrent cell decomposes into **existing** ops (gemm/slice/sigmoid/tanh/mul)
   with no new VM op — validated numerically against onnxruntime at ~1e-7.

The decomposition is ~17 nodes for an LSTM cell. Since the compiled VM's cost and
size scale with node count (not element count), the decision was to instead add
**fused cell kernels**: one node per cell. This is still "raw maths" (the design
doctrine), it just stops materialising the intermediate gate vectors and the
per-gate slice nodes.

## What changed

`src/shinro/runtime/linalg.zig` — three fused cells + a scalar-sigmoid helper:

- `lstm_cell(H, I, x, w, r, b, h_prev, c_prev) -> [2H]` — ONNX gate order `i,o,f,c`,
  Sigmoid on i/o/f, Tanh on the candidate and the output. Output is `h_next ‖ c_next`,
  matching ML-Agents' `recurrent_in`/`recurrent_out` layout (`[h ‖ c]`, h first —
  verified from a real model: `Slice_42 starts=0 -> initial_h`,
  `Slice_43 starts=128 -> initial_c`).
- `gru_cell(H, I, lbr, x, w, r, b, h_prev) -> [H]` — ONNX gate order `z,r,h`;
  `lbr` is a **comptime** parameter so the two reset placements constant-fold.
- `rnn_cell(H, I, x, w, r, b, h_prev) -> [H]` — Elman `tanh`.

All are comptime-dimensioned, take flat row-major slices, and use runtime inner
loops (no `inline for`, per the VM's code-size rule). The gate stack is read by
`H`-stride indexing into one `matvec` result per operand — no `slice` nodes and no
materialised `4H` pre-activation; the layout comes free from ONNX's gate-major
`W (4H, I)`.

`src/shinro/runtime/tests/linalg.zig` — 5 unit tests with f64 reference vectors
from the ORT-validated formulas, including a guard that `lbr` is not a no-op
(the classic silent bug).

## Key design decision: the GRU `linear_before_reset` trap

`linear_before_reset` moves the reset gate **across the recurrent matmul**, not just
the bias:

- `lbr=1`: `h = g(X·Whᵀ + r ⊙ (H·Rhᵀ + Rbh) + Wbh)`
- `lbr=0`: `h = g(X·Whᵀ + (r ⊙ H)·Rhᵀ + Rbh + Wbh)`

My first implementation had the two branches swapped (only the bias placement),
which silently diverged ~1e-1 — no error, just wrong numbers. Only a numeric oracle
against onnxruntime exposed it. Every real GRU found carries `lbr=1`. The kernel
therefore takes it as a comptime flag and a test asserts the two variants differ.

## Reference: the HF survey behind the model choices

Method: tag-search (`onnx` + reinforcement-learning / robotics / locomotion /
humanoid / quadruped) → 739 repos, 458 with `.onnx`, 3 514 files; range-read the
first 512 KB of each protobuf scanning for `LSTM`/`GRU`/`RNN` → 79 raw hits → 18
genuine recurrent models. HF robotics RL is overwhelmingly MLP (`Gemm`+`Elu`):
go2/g1/anymal/go1/hound/microduck/isaac exports are all memoryless.

Genuine recurrent robotics policies found:

- **GRU** — `astralhf/eco-drone-policies` (`policy_v26rnn_dr.onnx`: `state`+`h_in` →
  `action`+`h_out`; `policy_fw.onnx`: `state_window` → `action`),
  `wcompton/legged_locomotion_rl` (`maze_hum_wave_gru_5hz/.../policy.onnx`: G1
  humanoid, 2 stacked GRUs, vision inputs, `h_in` → `h_out`).
- **LSTM** — `cm107/agv-demo` (`AGVAgent.onnx`: AGV robot, ML-Agents format),
  `code3939/DecisionTransformer-Unity-Sim` (`BulletDodgeAgent.onnx`: ML-Agents).
- **vanilla RNN** — none on HF; validated against spec-built synthetic nodes.

Full-model gaps beyond the cell (for later): `Conv`/`LayerNormalization` (wcompton,
AGV vision), `Gather`/`Concat`/`Shape`/`ConstantOfShape` (shape glue),
`Multinomial`/`RandomNormalLike` (sampling). Closest to importable end-to-end: the
drone GRU (only `Gather` missing) and `BulletDodgeAgent` (only `Concat`,
`RandomNormalLike`). Note `wcompton/.../policy.onnx` does contain
`LayerNormalization` — so layernorm is not purely hypothetical for recurrent robots.
