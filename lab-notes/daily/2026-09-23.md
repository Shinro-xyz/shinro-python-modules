# 2026-09-23 — Recurrent-policy support: fused LSTM/GRU/RNN cell kernels

Branch: `feat/nn-kernel-support`

## Why

The ONNX importer can already lower memoryless policies (Gemm/Elu MLPs). The next
class of real robotics policies carries recurrence — an LSTM/GRU/RNN cell whose
hidden state must be fed back each tick. Two earlier findings framed the work:

1. A full HF survey (see below) showed recurrent robot policies *do* exist and are
   importable in principle, but they are rare; the ecosystem is overwhelmingly MLP.
2. The recurrent cell decomposes into **existing** ops (gemm/slice/sigmoid/tanh/mul)
   with no new VM op — validated numerically against onnxruntime at ~1e-7.

The decomposition is ~17 nodes for an LSTM cell. Since the compiled VM's cost and
size scale with node count (not element count), the decision was to instead add
**fused cell kernels**: one node per cell. This is still "raw maths" (the design
doctrine), it just stops materialising the intermediate gate vectors and the
per-gate slice nodes.

## What changed

`src/shinro/runtime/linalg.zig` — three fused cells + a scalar-sigmoid helper:

- `lstm_cell(H, I, x, w, r, b, h_prev, c_prev) -> [2H]` — ONNX gate order `i,o,f,c`,
  Sigmoid on i/o/f, Tanh on the candidate and the output. Output is `h_next ‖ c_next`,
  matching ML-Agents' `recurrent_in`/`recurrent_out` layout (`[h ‖ c]`, h first —
  verified from a real model: `Slice_42 starts=0 -> initial_h`,
  `Slice_43 starts=128 -> initial_c`).
- `gru_cell(H, I, lbr, x, w, r, b, h_prev) -> [H]` — ONNX gate order `z,r,h`;
  `lbr` is a **comptime** parameter so the two reset placements constant-fold.
- `rnn_cell(H, I, x, w, r, b, h_prev) -> [H]` — Elman `tanh`.

All are comptime-dimensioned, take flat row-major slices, and use runtime inner
loops (no `inline for`, per the VM's code-size rule). The gate stack is read by
`H`-stride indexing into one `matvec` result per operand — no `slice` nodes and no
materialised `4H` pre-activation; the layout comes free from ONNX's gate-major
`W (4H, I)`.

`src/shinro/runtime/tests/linalg.zig` — 5 unit tests with f64 reference vectors
from the ORT-validated formulas, including a guard that `lbr` is not a no-op
(the classic silent bug).

## Key design decision: the GRU `linear_before_reset` trap

`linear_before_reset` moves the reset gate **across the recurrent matmul**, not just
the bias:

- `lbr=1`: `h = g(X·Whᵀ + r ⊙ (H·Rhᵀ + Rbh) + Wbh)`
- `lbr=0`: `h = g(X·Whᵀ + (r ⊙ H)·Rhᵀ + Rbh + Wbh)`

My first implementation had the two branches swapped (only the bias placement),
which silently diverged ~1e-1 — no error, just wrong numbers. Only a numeric oracle
against onnxruntime exposed it. Every real GRU found carries `lbr=1`. The kernel
therefore takes it as a comptime flag and a test asserts the two variants differ.

## Reference: the HF survey behind the model choices

Method: tag-search (`onnx` + reinforcement-learning / robotics / locomotion /
humanoid / quadruped) → 739 repos, 458 with `.onnx`, 3 514 files; range-read the
first 512 KB of each protobuf scanning for `LSTM`/`GRU`/`RNN` → 79 raw hits → 18
genuine recurrent models. HF robotics RL is overwhelmingly MLP (`Gemm`+`Elu`):
go2/g1/anymal/go1/hound/microduck/isaac exports are all memoryless.

Genuine recurrent robotics policies found:

- **GRU** — `astralhf/eco-drone-policies` (`policy_v26rnn_dr.onnx`: `state`+`h_in` →
  `action`+`h_out`; `policy_fw.onnx`: `state_window` → `action`),
  `wcompton/legged_locomotion_rl` (`maze_hum_wave_gru_5hz/.../policy.onnx`: G1
  humanoid, 2 stacked GRUs, vision inputs, `h_in` → `h_out`).
- **LSTM** — `cm107/agv-demo` (`AGVAgent.onnx`: AGV robot, ML-Agents format),
  `code3939/DecisionTransformer-Unity-Sim` (`BulletDodgeAgent.onnx`: ML-Agents).
- **vanilla RNN** — none on HF; validated against spec-built synthetic nodes.

Full-model gaps beyond the cell (for later): `Conv`/`LayerNormalization` (wcompton,
AGV vision), `Gather`/`Concat`/`Shape`/`ConstantOfShape` (shape glue),
`Multinomial`/`RandomNormalLike` (sampling). Closest to importable end-to-end: the
drone GRU (only `Gather` missing) and `BulletDodgeAgent` (only `Concat`,
`RandomNormalLike`). Note `wcompton/.../policy.onnx` does contain
`LayerNormalization` — so layernorm is not purely hypothetical for recurrent robots.

## Step 2 — the cells are wired end-to-end and the importer + adapter support them

All six surfaces now carry the cells, so a recurrent ONNX policy imports and
compiles with no new dependency and no onnxruntime.

- **`ops.py`** — `lstm` / `gru` / `rnn` numpy handlers (the correctness oracle for
  `interpret`, the importer's eager evaluation, and the `.so`). Bit-exact against an
  independently written reference.
- **`trace_backend.py`** — `TraceBackend.lstm/gru/rnn`, so a component (not just the
  ONNX importer) can emit a cell. `H` is taken from the state operand so a
  mis-shaped `(w, h)` pair fails loudly.
- **`lower_zig.py`** — the three ops in the enum; `gru`'s `linear_before_reset`
  rides in the node's `aux` bit 0 (the `gemm` transB pattern) — no baked table
  needed, since it is a bool the VM folds into a comptime parameter.
- **`lower.zig`** — one VM arm per cell. `H`/`I` are derived **at comptime** from
  the weight and activation node shapes (`H = W.rows/4`, `I = X.rows*X.cols`), with
  `@compileError` gates on the gate-stack width, the input width, and the output
  slot size — a bad shape refuses to build instead of reading out of bounds.

### Importer: recurrence is live, never a frozen constant

`init`/`initial_c` are **bound to fresh graph input ports** and each cell publishes
its new state as a graph state output. The ONNX graph's own `initial_h` chain is
intercepted, so a policy exported with a baked zero state cannot silently become
memoryless — the same guard the composed estimator path has for a mutated attribute
without a placeholder.

Conventions that fell out of the real models:

- **`[h ‖ c]` in one port** — the LSTM kernel's output order equals ML-Agents'
  `recurrent_in` (verified from a real model: slice `0:H → initial_h`,
  `H:2H → initial_c`). A torch export with separate `h_in`/`c_in` binds two ports
  (`state_h_<k>`, `state_c_<k>`) and publishes one `state_hc_<k>`; the host splits it.
- **Per-cell ports** (`state_h_<k>`), so two stacked cells (the G1-humanoid shape)
  get independent state.
- **Reachability stops at the cells' initial-state slots**, so ML-Agents'
  `recurrent_in` and torch's `h_in`/`c_in` are not mistaken for extra policy inputs,
  and the glue around them (Slice/Concat for `recurrent_out`) is simply unreachable →
  not translated.
- `reshape` targets are collapsed to ≤2-D (`(1,1,I) → (I,)`); the VM is 1-D/2-D only.
- Loud rejects: bidirectional/reverse, `layout=1`, gate `clip`, `input_forget`,
  non-default `activations`/`alpha`/`beta`, `sequence_lens`, LSTM peepholes,
  num_directions≠1, seq/batch≠1, and a consumed sequence output `Y`.

### Adapter: state feedback

`_GraphPolicy` and `_CompiledPolicy` now carry a persistent state dict, merge it
into each tick's feed, and refill it from the state buffer afterwards;
`reset()` zeroes it (alongside the RNG reseed). `_state_feedback_plan` derives the
mapping from the port names, so `state_hc_<k>` splits into `state_h_<k>` and
`state_c_<k>` while GRU/RNN's `state_h_<k>` maps to itself.

## Step 3 — shape glue: a real HF recurrent policy now imports end-to-end

Measured first: for each target model, the *reachable* subgraph's op histogram
plus each unsupported op's consumers. That showed the glue is mostly metadata,
and only two small real models' gaps were reachable at all:

- drone GRU `policy_v26rnn_dr` / `policy_fw` — `Squeeze` + `Gather` only;
- `BulletDodgeAgent` — single-input `Concat`, `Squeeze`, `RandomNormalLike`;
- wcompton G1 / AGV — `Conv`/`LayerNormalization`/`LeakyRelu`, i.e. a vision
  problem, not shape glue.

So the glue layer needed **no new VM op**. `emit_shape_glue` translates ONNX's
integer-tensor shape algebra using the fact that every operand is known at
import time:

- `Shape` folds to a const of the input's statically-known dims;
- a fully-constant subtree folds to one `const` — the generic
  `Shape → Gather → Unsqueeze → Concat → Reshape` idiom collapses entirely;
- `Squeeze`/`Unsqueeze`/`Cast` become a `reshape` (only size-1 axes move, so the
  flat f64 order is preserved); `Cast` keeps its truncation semantics;
- `Transpose`/`Gather`/single-input `Concat` become a `reshape` when they only
  move size-1 axes, and are **rejected loudly** otherwise;
- the axes of `Squeeze`/`Unsqueeze` are read from either the attribute or the
  opset-13+ input tensor.

Two semantics decisions came out of the real models:

- **`Y ≡ Y_h` at seq == 1.** The drone policies read the sequence output `Y`
  through a `Squeeze → Transpose(perm longer than the rank) → Gather(last)`
  chain. With one step the sequence *is* the step, so `Y` binds to the same value
  as `Y_h` and the whole chain collapses to zero nodes. This replaced the old
  "sequence output not supported" rejection.
- **Collapsed leading axes are not real axes.** ONNX tensors here carry
  size-1 batch/seq/direction axes the VM drops, so a perm or axis index that
  refers to one is a no-op. `emit_transpose` pads the shape back out to judge the
  permutation, and drops exactly the padding it added — collapsing generically
  would stop at rank 2 and leave a spurious leading 1, which then read as a real
  axis and made the following `Gather` look like a data selection (that bug cost
  a debugging round).

Also fixed: the importer left the rank-3 `Reshape` node in the graph even after
squeezing its consumer; rank-3 targets are now collapsed at emission and any
other rank-3 tensor is refused.

## Next

  op for data-dependent selection.
- `RandomNormalLike` → the host-noise `epsilon` port, the doctrine-consistent
  mapping (RNG stays on the host); makes `BulletDodgeAgent` importable.
- A layernorm op, if/when a target policy needs it (wcompton's G1 GRU carries
  `LayerNormalization`; that model also needs `Conv`).
- Remaining shape glue for a *full* real-model import: `Gather`, `Concat`,
  `Shape`/`ConstantOfShape`, `Squeeze`/`Unsqueeze`, `Cast`; sampling
  (`Multinomial`/`RandomNormalLike` — the host-supplied epsilon port already
  covers the arithmetic).
- A committed recurrent ONNX fixture + a policy-only scenario, so the compile
  workflow is exercisable without regenerating weights.
