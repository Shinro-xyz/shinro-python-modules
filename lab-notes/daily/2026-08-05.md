### 2026-08-05 15:10 UTC — integration test environment brought to passing + CI independence

**What changed**

Completed and verified the full-loop integration test environment under `tests/integration/` (scaffold first landed in `ba2f495` on this branch; this session fixed the blockers and finished the wiring).

- **`tests/integration/`** — 5 test modules + `conftest.py` + `helpers/` + 4 scenario TOMLs, all gated behind `pytest.mark.integration`:
  - `test_base_tracking.py` — full closed loop Trajectory→Controller→Estimator→HolonomicMobileRobot→MuJoCo; parametrized over LQR/LQR+Luenberger/MPC_LTI/MPC_DeltaU.
  - `test_arm_cartesian.py` — PID+Kalman tracking a 6D end-effector lift schedule on the SO-ARM100.
  - `test_pick_and_place.py` — `phase_list` multi-plant feedforward (base+arm+jaw) through `RobotSim`.
  - `test_adversarial_integration.py` — NaN measurement injected at step 50 must raise, not corrupt control.
  - `test_scenario_factory.py` — construction validation + dimension-mismatch errors.
- **`helpers/scenario_runner.py`** — `run_scenario` (closed loop, single plant) and `run_phase_schedule` (feedforward multi-signal). Raises `ValueError` when the estimator propagates NaN/Inf — this is the agreed adversarial contract.
- **`factories/scenario_factory.py`** — clear `KeyError` for unknown plant names; optional controller/estimator sections (feedforward pick-and-place scenarios).
- **`configs/controllers/mpc_lti_base.toml`** — fixed a latent constraint-dimension bug: F = [I; −I] is 6 rows, so upper/lower bounds must be length 6 (was 3 → OSQP `Incorrect dimension of l`).
- **`configs/estimators/kalman_arm.toml`, `configs/plants/holonomic_base.toml`, `configs/trajectories/arm_lift.toml`** — arm estimator, base plant, and 6D arm lift configs.
- **CI independence**: `pyproject.toml` has `addopts = "-m 'not integration'"` so any `pytest` invocation skips the slow MuJoCo suite by default; `make test-integration` (or `run_tests.py --int`) opts in with `--override-ini="addopts="`. `tests/integration/conftest.py` adds a second safety net — `pytest.importorskip("mujoco")` + asset-existence check.
- **Removed** root `test_pick_and_place.py` (legacy, non-pytest, bypassed controllers/estimators) and the `test-pick-and-place` Makefile target. Old behavior is subsumed by `tests/integration/test_pick_and_place.py`.
- `demos/helpers.py` now hosts the shared `inject_free_joint` + `load_model_assets` (factored from the two demos that previously duplicated it).

**Key decisions**
- Adversarial policy: NaN/Inf measurements RAISE (runner throws `ValueError`) rather than silently corrupting control. Verified the Kalman filter currently propagates NaN — the integration test pins the raise behavior as the contract.
- Pick-and-place is feedforward (phase_list is a script of velocity setpoints), so it has no feedback controller/estimator; the schedule itself is the control.

**Test results**
- `make test-integration`: 32 passed (~28–45s; MuJoCo + LeKiwi assets required).
- `make test`: 744 passed, 33 deselected (32 integration + 1 slow MPC timeout) in ~3:44 — CI untouched, stays green.
- Empirical calibrations: base loop steady-state error ~7.6mm (LQR), ~5.5mm (MPC_DeltaU); arm EE ~3cm; pick-and-place drive reaches x≈1.35.

### 2026-08-05 19:30 UTC — packaging: `shinro` becomes an installable Python package

Restructured the repo into a `src/shinro/` package so it can be pip-installed
and continuously released. This was the last step of the "is it ready for
packaging treatment?" review — it was ready: the registry/factory/ABC pattern
and per-component `__init__.py` exports already existed, so this was a layout +
build-metadata change, not a code rewrite.

**What changed**
- Moved `components.py` + `controllers/`, `estimators/`, `plants/`,
  `trajectories/`, `utils/`, `factories/`, `simulation/`, `physics_engine/`,
  and `configs/` under `src/shinro/`. `configs/` (incl. a shipped default
  `robot_config.toml`) now live in the package so they ship with the wheel.
- Moved `shinro_mcp_server.py` → `src/shinro/mcp/server.py` with a `main()`
  entry point; installed as the `shinro-mcp` console command.
- Rewrote `pyproject.toml`: `[project]` metadata, `setuptools` + `setuptools-scm`
  build backend, `dynamic = ["version"]` from git tags, dependency ranges
  (`mcp>=1.28,<2`), optional extras (`mujoco`, `torch`, `lerobot`, `media`,
  `dev`), `[tool.setuptools.packages.find] where=["src"]`, and
  `package-data` for `configs/**/*.toml`.
- Added `utils/config_resolver.py`: factories still accept path strings, but
  relative `configs/...` names and bare filenames now resolve against the
  packaged configs via `importlib.resources`, falling back to CWD. Verified it
  works from an arbitrary CWD (post-install) and from a source checkout.
- Rewrote all internal imports from top-level (`from controllers...`) to
  `from shinro.controllers...`. `lekiwi_sim.py` stays at the repo root as a
  legacy, non-packaged script (imports patched).
- CI: added `pip install -e .`, version/import smoke checks, and updated the
  pyright path. `Makefile`: added `install` and `build` targets.
- `.gitignore` ignores the setuptools-scm-generated `src/shinro/_version.py`;
  added `MANIFEST.in`.

**Key decisions**
- `mcp` pinned `<2` — mcp 2.x removed `mcp.server.fastmcp`; caught by a fresh
  venv install, not by the pinned `requirements.txt`.
- Configs are resolved at the factory `__init__` via `resolve_config_path`,
  so the public factory string API is unchanged — existing tests/demos keep
  passing `"configs/controllers/lqr_base.toml"`.
- `simulation`/`physics_engine` import `mujoco` eagerly and therefore require
  the `[mujoco]` extra; the core package imports cleanly without it.

**Test results**
- `pip install -e .` clean; `import shinro` → `0.0.1.dev138+gc39d9b551`.
- Wheel built with `python -m build`; contains 19 config TOMLs; installed into
  a fresh venv and `ControllerFactory("configs/controllers/lqr_base.toml")`
  resolved against the packaged config.
- `pytest tests/` (default, minus slow MPC timeout): 525 passed, 219 skipped,
  33 deselected. MCP functional suite: 37 passed. Integration suite unchanged.
- `ruff check .` clean; `pyright` on the pyright-scoped modules: 0 errors.

**Files touched**
`pyproject.toml`, `MANIFEST.in`, `Makefile`, `.gitignore`, `requirements-dev.txt`,
`README.md`, `.github/workflows/ci.yml`, all `src/shinro/**` (moved + imports),
`src/shinro/utils/config_resolver.py` (new), `src/shinro/mcp/server.py` (moved +
`main()`), `tests/test_mcp_server*.py` (imports), `lekiwi_sim.py`, `demos/*`,
`scripts/generate_robot_config.py`.
