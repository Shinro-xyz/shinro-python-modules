# 2026-09-24 — Fused `layernorm` op (kernel + six-surface wiring + ONNX importer)

Branch: `feat/nn-kernel-support`

## Why

The recurring "next" item from the recurrent-policy work: `LayerNormalization`
is the one non-`Conv` op standing between the wcompton G1-humanoid GRU policy
(`wcompton/legged_locomotion_rl`) and an import. It is also the natural sibling
of the existing fused `softmax`/`gelu`/`elu` ops — a per-row reduction over the
last axis with two feature-length operands. Following the fused-op precedent
(`gemm`, the recurrent cells), it becomes **one** kernel/node rather than the
~6-node `mean → sub → pow → mean → add → rsqrt → mul → mul → add`
decomposition, which would materialize several full copies of the activation.

## What changed

`src/shinro/runtime/linalg.zig` — `layernorm_rows(rows, cols, a, scale, bias, comptime eps) -> [rows*cols]`,
treating the flat row-major buffer as `(samples, features)`: per row
`mean = Σa/cols`, biased `var = Σ(a-mean)²/cols`, `rstd = 1/sqrt(var+eps)`, then
`out = (a - mean) * rstd * scale + bias`. `scale`/`bias` are the ONNX
`Scale`/`B` feature vectors, fused into the same kernel (no separate `mul`/`add`
nodes). `eps` is a **comptime** parameter, so the whole kernel constant-folds
per node. This is the canonical torch `nn.LayerNorm` form: biased variance
(divide by `cols`), `eps` under the square root. Header doc comment states the
exact arithmetic contract (the three-way oracle needs the *same* expression in
the *same* order, not merely the same mathematics).

**Bug caught in review.** The first version had `return out;` *inside* the row
loop, so it returned after row 0 and left rows `1..n` `undefined`. That is the
worst failure shape: silently correct for any single-row (`vec`) input, garbage
otherwise, no error. Moved the `return` below the loop and added a two-row unit
test explicitly as the regression guard. (Also renamed to `_rows`, matching the
`softmax_rows` convention, and cleaned a trailing-whitespace line.)

## Key decision: `eps` is baked, not an input port

`LayerNormalization`'s `epsilon` is an **attribute** — a model constant frozen
at export. It rides the same mechanism as `elu`'s `alpha`: an `f64` cannot live
in the node's single `aux: usize`, so `lower_zig.py` bakes it into a parallel
`layernorm_eps: [f64]` table and stores the table index in `aux`. Making it a
C-ABI **input port** was the alternative and was rejected: ports are for values
that change per call (state, MPPI's `epsilon` noise, SMC's `f_x`/`g_x`), and a
port would force the host to repack the same constant every tick forever while
muddying the manifest. Attribute-in ⇒ compile-time-baked is the consistent rule
(elu alpha, gemm alpha/beta, gru `linear_before_reset`).

## Wiring (all six surfaces)

- **`ops.py`** — `layernorm` numpy handler (the correctness oracle for
  `interpret`, the importer's eager evaluation, and the `.so`). Uses the
  identical reciprocal-then-multiply order as the kernel.
- **`trace_backend.py`** — `TraceBackend.layernorm(x, scale, bias, *, eps=1e-5)`,
  shape-preserving (like `softmax`).
- **`lower_zig.py`** — enum variant, `layernorm_eps` table + `layernorm_aux`
  map (the `elu_alpha` pattern), threaded through `_node_line` /
  `_graph_manifest` / `_node_vm_info` (the single source of truth for
  `(vm_op, aux)`, which the drift guard cross-checks).
- **`lower.zig`** — VM arm next to `.elu`; operands via `node_input` +
  `node_input_at` (the `gemm` multi-operand shape); a `comptime { … @compileError }`
  gate that `scale`/`bias` are exactly the `(cols,)` feature vector; `1-D`
  handled the `softmax` way (`rows=n, cols=1, vec=true` ⇒
  `layernorm_rows(1, n)`, never `n` rows of length 1).
- **`onnx_import.py`** — `LayerNormalization` added to `_SUPPORTED_OPS` and an
  `emit_layernorm` translator: last-axis only (same axis rule as `Softmax`), a
  missing optional `B` emitted as an explicit **zero feature-vector** (the
  comptime gate needs one entry per feature, so a scalar won't do), and loud
  rejects for a non-last `axis` and `stash_type != 1`.
- **tests** — Zig unit tests (multi-row, scale/bias, eps floor), a `.so` oracle
  graph (2-D multi-row, 1-D single-row, non-default `eps`) diffed against both
  `interpret()` and an independently written numpy reference, op-shape-matrix
  cells (`layernorm_2d`, `layernorm_2d_eps`, `layernorm_1d`), and four importer
  tests (scale+bias, missing-bias-as-zeros, non-last-axis reject, `stash_type`
  reject).

## Follow-up — conditioning + operand-shape coverage

The initial test set was narrow in two ways: every case was ≤5 features, and all
operands were the 1-D `(cols,)` form. Both were closed.

- **Width-128 large-offset cell** (`.so` oracle). `ln128` normalizes a
  128-feature row fed as `x = 1e9 + (arange(128) - 63.5) + N(0, 0.5)` — a large
  offset with an O(1) spread, the condition-number regime where the one-pass
  `E[x²] − mean²` variance loses ~9 significant digits. Measured over 20 feeds:
  `|.so − interpret|` and `|.so − two-pass reference|` both **3.4e-08**, while
  `|.so − naive one-pass|` is **4.0e-01** (~1.2e7×). The cell is deliberately
  *not* compared at bit-parity — the f64 mean of ~1e9-magnitude values is itself
  only good to ~1e-6, so the tolerance is `atol=1e-4` and the load-bearing
  assertion is the two-pass-vs-naive gap (`err_two < 1e-4`, `err_naive > 1e-2`,
  `err_two < 0.05·err_naive`). That gap *is* the anti-cancellation property.
- **`(1, cols)` operand cell** (`layernorm_2d_row_operands` in the shape
  matrix) pins that the VM comptime gate accepts any operand with
  `rows*cols == cols` and that the kernel indexes the flat buffer by feature,
  not by rank.

Re-verified: `make lint` clean; `test_zig_lowering` + `test_op_shape_matrix` →
**97 passed, 2 skipped** (the two pre-existing `sign` skips).

## Perf — const nodes are no longer copied into the workspace

Branch: `feat/nn-kernel-support`. Separately from layernorm, investigated the
NN-kernel perf gap on the Pi. The first thing the measurement found was not a
naive loop — it was a redundant weights memcpy.

### Why

The VM's `.cst` arm copied every baked constant out of `g.const_blob` into its
workspace slot on **every tick**, and consumers read it back out of the
workspace. For a control graph the constants are a few KiB (cartpole LQR+KF:
188 f64 = 1.5 KB), so this was invisible and had never been measured with an
MLP-sized constant. For an ONNX policy the constants *are* the workspace —
microduck: `const_blob_bytes` 1,583,184 of `buf_bytes` 1,599,544 — so each tick
did a full **1.58 MB weights memcpy** (read + write, zero flops) *before* the
kernel read the same weights again.

It wasn't a deliberate decision: the VM gives every node a workspace slot (the
offset table is uniform) and every input is read from the workspace (uniform
`node_input_at`), and those two choices together force a const node to
materialize its value into its slot. Correct and simple for kilobyte constants;
wrong at megabyte scale.

### What changed

`src/shinro/runtime/lower.zig`, two spots:

- `.cst` becomes a no-op (it no longer writes its slot).
- `node_input_at` special-cases a `.cst` source and returns the `const_blob`
  slice directly; every other node keeps the workspace contract unchanged.

The conditional is free — the op is a comptime constant in the unrolled node
loop, so each consumer compiles to either a blob read or a workspace read. The
values are **bit-identical** (same bytes, just not copied), so no oracle
tolerance moved. The const workspace slots still exist (offset table unchanged);
removing them is a separate, perf-neutral cleanup.

### Measured (Pi 3 B+, bare kernel, 100k ticks, CLOCK_MONOTONIC_RAW)

| policy | const blob | before (median) | after (median) | speedup | 1 kHz |
| --- | --- | --- | --- | --- | --- |
| microduck | 1.58 MB | 2973.4 µs | **1527.3 µs** | **1.95×** | 336→655 Hz, still misses |
| go2 | 1.52 MB | 2773.0 µs | **1406.3 µs** | **1.97×** | 711 Hz, misses |
| drone_gru | 0.71 MB | 1293.4 µs | **653.3 µs** | **1.98×** | **1531 Hz, 0% miss** |
| toy_lstm | 1.3 kB | 22.60 µs | 22.76 µs | 1.00× | unchanged |

microduck WCET 10961 → 2081 µs. The uniform ~2× on weight-carrying policies and
unchanged small-const toy_lstm is the signature of removing a redundant full
memcpy.

**Classical controls are unaffected** — same-session A/B on cartpole LQR+KF
(300k ticks): before median 21.875 µs / mean 22.26, after 22.396 / 22.76, p99
flat, WCET 425→405. A ~3 KB copy is sub-µs and cache-resident; the effect is
noise. Confirms the earlier finding that classical kernels are not memory-bound
(they sit at ~20 µs with 0 misses).

### Where the time goes now

The tick now scales linearly with const size (1.58 MB→1527 µs, 0.71 MB→653 µs,
both ≈ **1.05 GB/s**), and a `memmove` probe on the Pi costs 1285 µs for 1.58 MB
(2.46 GB/s r+w). So the remainder is dominated by *streaming the weights from
DRAM*, not by the scalar reduction loops. **SIMD compute would not be the next
lever** — fewer weight bytes would be. Verified 100.0000% of the microduck/go2
const elements are f32-exact (their ONNX initializers are float32), so an f32
const blob with widen-on-read would be bit-identical and halve the dominant
traffic. Not implemented yet — a separate decision.
