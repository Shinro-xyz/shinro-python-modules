# 2026-10-13 — LTISystemsAnalyzer robustness: stability gate + list coercion

Branch: `main`

## Why

The LTI analyzer (`src/shinro/utils/controllability_checker.py`) is a public
utility exposed through the MCP server, and it had two defects that turned a
diagnostic tool into a crash:

1. **`summary()` raised on an unstable-but-controllable system.** It gated the
   Gramian sections on `is_controllable()` / `is_observable()` — *rank* tests —
   while `controllability_gramian()` requires *stability* (Hurwitz A). An
   unstable A such as `[[0,1],[1,0]]` (eigenvalues ±1) is rank-controllable, so
   `summary()` reached the infinite-horizon Gramian and raised
   `ValueError: A is not Hurwitz`. The `*not defined* (unstable A)` branches
   already existed in `summary()` — the gate made them unreachable. The
   trailing unconditional `hankel_singular_values()` would have crashed the same
   way.
2. **Raw list matrices crashed later.** The constructor used `A.shape[0]`
   directly, so `A=[[0,1],[-1,-2]]` raised
   `AttributeError: 'list' object has no attribute 'shape'` before any analysis.

This was picked up while surveying non-component work; the only open issue
(#18) is a pure component backlog, so analyzer robustness was untracked.

## Change

`src/shinro/utils/controllability_checker.py`:

- Added **`_is_hurwitz()`** (every eigenvalue has strictly negative real part).
  `summary()` now gates the controllability/observability Gramians on stability,
  not rank, so an unstable system reports `*not defined* (unstable A)` instead of
  raising; the Hankel section is emitted only when both Gramians exist.
- The duplicated inline eigenvalue checks in `controllability_gramian()` and
  `observability_gramian()` now call `_is_hurwitz()` (behaviour-preserving).
- Added **`_coerce()`** — converts Python `list`/`tuple` to a backend array and
  passes arrays and sparse matrices through unchanged; applied to A/B/C/D in
  `__init__`. Constructor signature widened to a new `MatrixLike` alias
  (`np.ndarray | list | sparray | spmatrix`) so the accepted forms are truthful.

Tests:

- `tests/test_controllability_checker.py` — new `TestSummaryRobustness` (unstable
  `summary()` does not raise and reports undefined Gramians; stable system still
  gets the Hankel section; `_is_hurwitz` matches eigenvalue signs) and
  `TestListInputCoercion` (list matrices accepted; list and array inputs give an
  identical Gramian and `rank_report`).
- `tests/test_adversarial.py` — `test_summary_on_zero_system` **asserted the crash
  as intended behaviour** (`pytest.raises(ValueError)`). Rewritten to pin the
  corrected behaviour. Worth recording: the old test encoded the bug as the
  spec, which is why it survived.
