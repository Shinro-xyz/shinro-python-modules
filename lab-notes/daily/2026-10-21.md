# 2026-10-21 — Outbound license set to Apache-2.0

## Context

The license audit (2026-10-13) flagged the outbound license as unset: `LICENSE`
was 0 bytes and `pyproject.toml` deliberately carried no `license` field, with a
comment saying the choice was pending legal review. Commit `50ec282` ("Add
LICENSE file") committed the Apache License 2.0 text (201 lines), but the
packaging metadata still said nothing, and `README.md` still told readers the
license was undecided and the `LICENSE` file empty — a contradiction and a stale
claim in the published docs.

## Change

`pyproject.toml`:

- `license = "Apache-2.0"` — PEP 639 license **expression**, not the legacy
  `{ text = ... }` table (which setuptools deprecated and which never produced a
  machine-readable `License-Expression`).
- `license-files = ["LICENSE", "THIRD-PARTY.md", "licenses/*"]` — closes the
  other half of the audit finding: `MANIFEST.in` only covered the **sdist**, so
  the wheel shipped a 0-byte `LICENSE` and no attribution. With `license-files`
  the files land in `dist-info/licenses/` and are emitted as `License-File`
  metadata, which is what Apache-2.0 §4(b) requires of us for the vendored OSQP
  code.
- `build-system.requires` floor raised `setuptools>=68` → `setuptools>=77`, the
  release that implements PEP 639 `license`/`license-files` under `[project]`.
  Without the bump an isolated build env resolved to a setuptools that silently
  ignores both keys.
- Replaced the "undecided, deliberately" NOTE with the rationale above, plus a
  warning not to add `License :: OSI Approved :: ...` classifiers — setuptools
  ≥77 rejects a license classifier alongside a PEP 639 expression.

`README.md`: the Licensing section now states Apache-2.0 and points at
`LICENSE`; the stale "Undecided — pending legal review / intentionally empty"
paragraph is gone. `THIRD-PARTY.md` was already correct (its "compatible with
this project's outbound license" line is now concrete).

`MANIFEST.in` left as-is — it is a no-op for these files now and still harmless
for the sdist.

## Verification

`python3 -m build --wheel --sdist` (setuptools 82.0.1):

- `Metadata-Version: 2.4`, `License-Expression: Apache-2.0`
- `License-File: LICENSE`, `THIRD-PARTY.md`, `licenses/Apache-2.0.txt`,
  `licenses/OSQP-NOTICE.txt`
- wheel payload: `*.dist-info/licenses/{LICENSE,THIRD-PARTY.md,licenses/*}`
  (11558 / 2823 / 11358 / 419 bytes — no longer empty)
- sdist carries the same four paths at the archive root
- `ruff check .` clean

## Notes

The sibling `microduck_rl` repo already uses the same PEP 639 shape
(`license = "Apache-2.0 AND CC-BY-NC-SA-4.0"` + `license-files`), so this brings
shinro in line with the org's newer packaging convention rather than the legacy
`{text = ...}` + classifier form still in `llm-multiagent-swarm`.
