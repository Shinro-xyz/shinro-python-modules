### 2026-09-01 23:55 UTC — MPC controllers compose: role-based controller wiring + KF+MPC_LTI .so

**The gap:** `compose()` hardcoded the controller as `compute(current_state, target_state)`, so only LQR/PID composed. MPC_LTI (`compute(x0)`) and MPC_DeltaU (`compute(x0, u_prev)`) couldn't be composed with an estimator — the MPC test had to bypass compose and wrap the traced graph directly. MPPI/SMC have other blockers (see "parked").

**Controller role mapping (compose.py):** controller inputs are now mapped by *role* from the traced graph's input placeholders (the compute() signature), via an exact-name table `_CONTROLLER_INPUT_ROLES`:

- `state` (`x0`, `current_state`, `state`, `x`) → the state estimate
- `reference` (`x_ref`, `target_state`, `target`) → the reference trajectory
- `u_prev` → the shared previous-control recurrent port (the same one the estimator consumes)

**Regulator reference handling (the design decision):** MPC_LTI/MPC_DeltaU have no reference input — they regulate to origin. When the controller declares a state but no reference, compose emits `e = x_hat - x_ref` (a `sub` node) and feeds the *error state* instead: regulating e→0 tracks x_ref. This is exact for the base plant (A = I: the error dynamics `e' = A e + Bu + (A−I)x_ref` lose the feedforward term). General A would need an `(A−I)x_ref` feedforward — documented in docs/codegen.md as a known approximation. Keeping the subtraction in compose (not in the controller) means `MPC_LTI.compute(x0)` is untouched and the emosqp bake stays valid — the QP still regulates its input to zero; only the per-tick `q = Fᵀ·error` changes.

**`u_prev` routing (MPC_DeltaU):** the composed graph already had `u_prev` as a recurrent input (estimator feed) and `state_u_prev = u` as an output. DeltaU's controller input just points at the same `u_prev` port — no new state machinery; the loop closes for free.
