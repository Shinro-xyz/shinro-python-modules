### 2026-08-24 — XLA-style tracing layer landed (slice a)

**What was built.** A new `src/shinro/codegen/` subpackage implementing the
tracing model we designed over the last several sessions. This is slice (a)
of the "compile the control loop to a native `.so`" pipeline: tracer +
interpreter + composition, all Python, no Zig yet. The tracer captures a
component's math as a primitive graph by running it once with abstract
`Tracer` values; the interpreter replays the graph on real numpy inputs
(the correctness oracle); the composition pass stitches per-node graphs
into one closed-loop step graph per the fixed ABC dataflow.

**Why.** The deployed `.so` (slice b, future) must be guaranteed to agree
with the Python loop. The tracing model — where the graph *is* the Python
execution, transcribed — makes disagreement structurally impossible: the
only thing that can be wrong is the ~20 primitive lowerings, which are
verified once against `NumpyBackend` and reused for every component. Slice
(a) proves the tracer is sound before any Zig exists.

**Key design decisions.**

- **Pure-registry op dispatch** (no if/elif ladder). `ops.py` is a dict of
  `@register_op` handlers; the interpreter is a 5-line loop over
  `OP_HANDLERS[node.op]`. Adding a new op is one decorator — no interpreter
  edit. This is the extensible "switch" the user asked for.
- **Auto-inferred contracts** (no per-component metadata). `infer_contract.py`
  derives a component's I/O surface from its ABC (`Controller` → `compute`,
  `StateEstimator` → `estimate`) and `inspect.signature`. A new component
  added with `@register_controller("Foo")` + `from_config` + a standard
  `compute(self, current, target)` signature traces with zero tracer-side
  code — the "out of the box" property.
- **Attr-diff state detection.** The tracer snapshots every array-valued
  instance attr's `id()` before the call; any attr whose `id()` changed
  after is flagged as recurrent state (e.g. `KalmanFilter.x_hat`). No
  hand-declared state slot registry.
- **Auto-wiring composition.** The wiring is the fixed ABC dataflow
  (`estimator → controller`), not a per-scenario edge dict. Shape mismatches
  between estimator and controller (KF's `(n,1)` column vectors vs LQR's
  `(n,)` flat) are resolved by auto-inserting `reshape` nodes — the XLA
  approach.
- **`__array_ufunc__ = None` on `Tracer`.** The `ArrayBackend` docstring
  notes that `@` is intentionally not wrapped by the backend, so the tracer
  intercepts `@` at the value level via `__rmatmul__`. Without disabling
  `__array_ufunc__`, numpy would silently coerce the tracer to an array
  and compute with garbage instead of recording a node.

**Bugs found and fixed during the build.**

1. **Stale Tracer leak across traces.** The KF's `self.P` (covariance) gets
   reassigned to a `Tracer` during a traced call (because `K_gain` is a
   Tracer and `(I - K_gain @ C) @ P` propagates Tracer-ness). On the next
   trace, the stale `Tracer` referenced dead node ids from the previous
   graph → `KeyError`. Fix: `trace_node` now snapshots *all* array attrs
   before the call and restores them in a `finally`, so a traced call never
   leaves the component polluted.
2. **2D @ 1D matmul rejected.** `LQR.compute` does `self.K @ error` where
   `K` is `(3,3)` and `error` is `(3,)` — numpy allows this (treats 1D as a
   column vector, returns 1D), but the tracer's shape-check rejected it.
   Fix: `_matmul_out_shape` now handles all three numpy matmul shape
   conventions (2D@2D, 2D@1D, 1D@2D).
3. **Real ndarrays passed to `bk.*` methods.** The KF's covariance update
   `P = A P Aᵀ + Q` involves only real arrays (no Tracer), so `@` computes
   for real and `S` arrives at `bk.inv(S)` as a real ndarray, not a Tracer.
   Fix: `TraceBackend._emit` lifts any concrete ndarrays to `const` nodes
   before emitting — the all-const subgraph gets baked, which is correct
   (it would be folded regardless).
4. **Composition pass placeholder rewiring.** Initial design copied
   `input` nodes from subgraphs into the combined graph, then rewired
   consumers — but the placeholder `input` nodes themselves still got
   interpreted and looked up names that weren't in the combined inputs.
   Fix: `_merge_and_rewire` skips `input` nodes entirely and rewires
   consumers directly to the combined-graph source nodes (with auto-reshape).
