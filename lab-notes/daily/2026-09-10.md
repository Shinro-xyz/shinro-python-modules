### 2026-09-10 19:23 UTC — update

**Strict config dataclasses for LQR / PID / MPC (DX audit follow-up).**

Started from a DX audit of the package from an external user's perspective. The
first concrete change: replace the raw-dict `from_config` path for the three
most-used controllers with strict, typed config dataclasses that parse TOML
directly, so authoring typos surface at parse time instead of mid-simulation.

What was built:

- **`src/shinro/utils/config_spec.py`** (new) — `strict_from_dict` / `config_from_toml`.
  A config dataclass's fields ARE the schema: unknown keys, a mismatched `type`
  key, and missing required fields all raise `ValueError` naming the component
  and listing valid keys. `type` is validated against the registered name and
  dropped (absent `type` is fine — MCP inline params don't carry it).
- **`LQRConfig`** (lqr.py) — `state_cost`/`control_cost` required; `dt`,
  `A_dynamics`, `B_dynamics` optional (None = plant-derived in scenario builds).
  Fixed the eager-default bug: `config.get("B_dynamics", config["dt"] * eye(n))`
  evaluated `config["dt"]` even when `B_dynamics` was present, so `dt` could
  never be omitted. Now lazy, with a clear error when neither is supplied
  standalone.
- **`PIDConfig` + `LimitsConfig`** (pid.py) — gains keep their existing defaults
  (kp→[1.0], ki/kd→zeros) so the MCP server's inline-params path and the suite
  stay green; `output_limits` nested table is strict-parsed recursively. `dt`
  required at runtime with an error that teaches the plant-injection rule.
- **`MPCConfig` / `MPCDeltaUConfig` / `ConstraintsConfig`** (mpc_lti.py) —
  `horizon`/`state_cost`/`control_cost` required, `terminal_cost` defaults to
  `state_cost`, `constraints` nested table strict-parsed. `MPCDeltaUConfig`
  subclasses `MPCConfig` via `kw_only=True` (sidesteps dataclass field-ordering),
  so `delta_u_penalty` is required for DeltaU and rejected as unknown for plain
  MPC_LTI.
- Each controller exposes `Config = <...>Config` for discoverability.
- `from_config` still accepts raw dicts (the `isinstance(config, dict)` shim),
  so factories, codegen (`build_composed_graph`), and MCP are untouched.

Design decisions:

- TOML stays the only authoring surface; the dataclass is the parser, not a
  parallel representation. Provenance still hashes raw file bytes.
- `dt`/`A_dynamics`/`B_dynamics` optional-with-None is the seam for the planned
  plant-derived injection (`inject_dt`/`inject_model` via `dataclasses.replace`)
  — not wired yet, that's the next step.
- PID gains kept optional deliberately: the strictness win is rejecting unknown
  keys and wrong `type`, not forcing gains that have a sane P-controller default.

Test changes:

- `tests/test_factories.py::test_create_missing_required_key` — now expects
  `ValueError` (with the missing key named) instead of bare `KeyError`.

Verification:

- `make test`: 1055 passed, 5 skipped, 96 deselected (integration/mcp markers).
- `make lint`: ruff clean, pyright 0 errors on the scoped dirs.
- Smoke-tested the three error classes (typo / wrong type / missing required)
  and the `config_from_toml` path against `lqr_cartpole.toml`.

Next steps (not done): plant-derived `dt`/model injection via `dataclasses.replace`
in `ScenarioFactory._create_loop_role` and `gen_scenario`; add the plant config to
`_provenance`; cookie-cut the remaining controllers/estimators/trajectories onto
the same pattern; `Scenario.run()` public API.

**ConfigDriven ABC mixin + Tier-1 cookie-cut (estimators + remaining loop controllers).**

Extended the strict-config pattern from three controllers to the whole
control loop, with framework-level enforcement so new components are forced
to declare their schema.

What was built:

- **`ConfigDriven` mixin** (components.py) — `Config: ClassVar` + `parse_config`
  classmethod that strict-parses a TOML dict into `cls.Config` using the
  component's registry name (fallback: class name for unregistered bases).
  Applied to `Controller` and `StateEstimator` ABCs (`PhysicsEngine` excluded —
  engines are constructed directly). LQR/PID/MPC `from_config` refactored to the
  one-line `cls.parse_config(config)` idiom; nested-table parses (LimitsConfig,
  ConstraintsConfig) keep using `strict_from_dict` directly.
- **Estimators cookie-cut (enforced)**: `KalmanFilterConfig`, `LuenbergerObserverConfig`
  — process_noise/measurement_noise or observer_gain required; dt/A/B/C/D optional
  with lazy defaults. Both had the eager-`config["dt"]` bug (KeyError even when
  `B_dynamics` present) — fixed.
- **Controllers cookie-cut (warned)**: `SMCConfig` (c, k1 required; phi/k2/smoother/
  alpha optional; dt accepted-but-unused for TOML compat), `MPPIConfig`
  (num_samples/temperature/horizon/noise_sigma required; dt optional-with-runtime
  error like PID; state_cost/control_cost as TOML-authorable fields; dynamics_fn/
  cost_fn deliberately NOT in the schema — they're runtime-injected callables).
- **Registry enforcement** (factories/registry.py): `_check_config` helper;
  `register_estimator` raises `TypeError` at import (both estimators migrated);
  `register_controller` emits a `UserWarning` naming the class and pointing at
  LQRConfig — fires only for `onnx_rl`/`lerobot_diffusion` (pending rewrite:
  their NN runtimes are untraceable to the codegen VM and will be rewritten,
  at which point this flips to strict).

Design notes:

- Non-TOML values (MPPI callables, engine handles) are deliberately outside the
  schema — the dataclass declares only what's authorable in TOML; from_config
  handles runtime injection. This forces the config-vs-injected boundary to be explicit.
- MPPI/SMC/estimators all follow the LQR template: required fields strict,
  `dt`/`A_dynamics`/`B_dynamics` optional-None as the seam for the future
  plant-derived injection.

Tests: added `TestRegistryConfigEnforcement` in test_factories.py (estimator
without Config raises; controller without Config warns + registers; all built-in
estimators + loop controllers assert Config present). One pre-existing test

**Plant-derived dt/model injection — the plant TOML is now the single source of physics truth everywhere.**

Closed the loop on the dt duplication: controller/estimator configs no longer
need to restate `dt` (or the model) in any scenario-driven build. Precedence:
**explicit wins, derived fills, disagreement is loud.**

What was built:

- **`inject_plant_derived(cfg, plant, *, with_model)`** (linearization.py) —
  operates on Config dataclass instances via `dataclasses.replace`: fills `dt`
  from `plant.dt` when omitted, raises a loud `ValueError` on disagreement
  (a mismatched PID/MPPI dt silently mis-scales integration — now impossible),
  and with `with_model` derives `A_dynamics`/`B_dynamics` via `derive_model`
  when the config declares neither (injected as TOML-serializable lists so the
  resolved config stays serializable). The `with_model` kwarg name avoids
  shadowing the module-level `derive_model` function (caught by the new tests).
- **`ConfigDriven.load_config(config, plant=None, derive_model=False)`**
  (components.py) — strict-parse (TOML path or dict) → injection. This is the

- **Factories**: `ControllerFactory.create(backend, plant, derive_model)` and
  the Estimator twin. `ScenarioFactory._create_loop_role` now just passes
  `plant` through. Semantics: dt fill+disagreement-check applies in **both**
  sim-backed and plant-only modes (all shipped sim configs agree at 0.02);
  model derivation only in plant-only mode, preserving the "sim-backed
  velocity-commanded defaults untouched" contract.
- **Compile path** (scenario_gen): resolves the estimator/controller registry
  classes (type read from the scenario TOML, or from the component's own TOML

  derivation was used — the master build hash commits to every input file.

  `kalman_cartpole.toml`, and `luenberger_cartpole.toml` — these are shared by
  the plant-only sim scenario (cartpole_balance) and the derived compile
  scenario (cartpole_lqr_kf_derived), so both pipelines now prove injection.
  The estimator parity guard was updated to allow dt-less (plant-inherited)
  twin pairs.

### 2026-09-10 22:17 UTC — update

**`Scenario.run()` — the public simulation API (closes the DX gap from the audit).**

A scenario TOML is now a runnable simulation: `ScenarioFactory.build()` returns
a `Scenario` whose `run()` executes the whole loop, driven entirely by the
TOML (duration, dt, noise, adversarial faults, input limits, tolerances). This
was the missing middle step of the ideal workflow — previously the only correct
loop lived in `tests/integration/helpers/scenario_runner.py`, which isn't
installed.

What was built:

- **`src/shinro/simulation/runner.py`** (new) — the runners moved out of the
  test suite into the package:
  - `StepRecord` (moved unchanged) and `SimResult` (new): list-like wrapper
    (`__iter__`/`__getitem__`/`__len__` delegate to records, so existing test
    helpers work on it), stacked-array properties (`true_state`, `estimated`,
    `control`, `t`, ...), `steady_state_error(tail)` / `estimator_error(tail)`,
    and `check()` — applies `[scenario.tolerance]` from the TOML and returns a
    report, never raises (assertion helpers belong to tests).
  - `iter_scenario` / `iter_phase_schedule` generators as the core (live
    rendering / early-stop), `run_scenario` / `run_phase_schedule` collectors.
  - `_compute_control` dispatch (the isinstance adapter absorbing the
    per-controller `compute()` signatures) moved unchanged.
  - Two latent fixes: the noise RNG seed now honors `[noise.measurement].seed`
    (param overrides), and a too-short trajectory warns instead of silently
    truncating.
- **`Scenario.run()` / `iter_run()` / `reset()`** (scenario_factory.py) —
  `run()` branches on `controller is None` (closed-loop vs feedforward), so the
  user never knows `run_phase_schedule` exists. `reset()` restores the TOML
  initial state and clears controller/estimator state; deterministic
  reproduction is `scenario.reset(); scenario.run(seed=0)`.
- **Lazy `simulation/__init__.py`** (PEP 562 `__getattr__`) — `RobotSim`
  imports mujoco at module load (an optional extra); deferring it means
  `import shinro.simulation.runner` and plant-only scenarios work on a minimal
  install. The runner itself imports no mujoco.
- **Test shim** — `tests/integration/helpers/scenario_runner.py` re-exports
  from the package, so the 6 integration test files work unchanged.
- **New tests** (`tests/test_scenario_run.py`, plant-only, no mujoco): run
  returns SimResult with correct shapes, defaults to duration, iter_run yields
  records, seed determinism (with reset), trajectory-cap warning, reset
  restores initial state + clears estimator, check() applies TOML tolerances
  and never raises, feedforward branch routes to the phase runner.

Verification: `make test` 1078 passed; integration 58 passed (via the shim);
`make lint` ruff + pyright clean.

Remaining: OnnxRL/LeRobot rewrite (flips register_controller to strict);
normalize `compute(estimate, reference, u_prev=None)` across controllers to
collapse the `_compute_control` dispatch; docs/quickstart update for the new
`scenario.run()` workflow.

### 2026-09-10 23:40 UTC — update

**Normalized `compute()` — the runner dispatch collapsed to a uniform call.**

Every scenario-runnable controller now shares the signature
``compute(current_state, target_state=None)``: LQR/PID regulate
``current_state`` toward ``target_state``; MPC forms the tracking error
``e = current_state - target_state`` internally (previously the runner/compose
pre-subtracted and passed the error as ``x0``); MPPI tracks ``target_state``
(previously ``x_ref``). The isinstance chain in the runner is gone.

What changed:

- **MPC_LTI.compute(x0)** → ``compute(current_state, target_state=None)`` —
  ``x0 = current_state - target_state`` internally, preserving the exact
  sign convention (error = x_hat - x_ref). ``MPC_LTI_DeltaU.compute(x0, u_prev)``
  → ``compute(current_state, target_state=None, u_prev=None)``.
- **MPPI.compute(x0, x_ref=None)** → ``compute(current_state, target_state=None)``.
- **LQR/PID** — already ``(current_state, target_state)``; unchanged.
- **Runner** — ``_compute_control`` collapsed to a uniform
  ``ctrl.compute(estimate, reference)`` call. Two one-time (not per-step)
  contract checks in ``iter_scenario``: SMC (needs f_x/g_x dynamics a scenario
  doesn't wire) raises ``NotImplementedError``; ``u_prev`` is passed only to
  controllers that declare it (MPC_DeltaU), via a single
  ``inspect.signature`` check — not an isinstance chain.
- **compose.py** — docstrings updated: built-in controllers now take a
  reference input (MPC forms the error internally); the regulator branch
  (error-state feed for a custom ``compute(x0)`` controller) is retained for
  custom controllers. ``_CONTROLLER_INPUT_ROLES`` already mapped
  ``current_state``/``target_state``, so no wiring change was needed.

Design decision worth noting: I initially added ``u_prev=None`` to *every*
controller signature for strict uniformity, but that forces every
``trace_node`` call site to declare a ``u_prev`` shape (~15 sites, fragile —
the traced graph derives its input ports from the signature). Reverted to
``u_prev`` only on DeltaU (the one that uses it) + a one-time signature check
in the runner. Same dispatch collapse, zero trace churn, and future
controllers that want ``u_prev`` just declare it.

Test fallout (all mechanical): MPC/DeltaU trace ``input_shapes`` renamed
``x0`` → ``current_state``/``target_state`` (test_codegen_compose, the zig
``_build_mpc_graph`` + ``TestSolveQpOracle``); the DeltaU live-oracle calls
``mpc.compute(x_hat - x_ref, u_prev)`` needed ``u_prev=`` keyword (the second
positional arg is now ``target_state`` — caught by the compose + zig oracles);
MPPI test ``compute(x, x_ref=x_ref)`` → ``compute(x, x_ref)``. The composed
MPC oracles needed no change — ``mpc.compute(x_hat - x_ref)`` still yields the
same error (target_state=None → error = current - 0).

Verification: `make test` 1078 passed; integration 58 passed; `make lint`
ruff + pyright clean.

docs/quickstart update for the `scenario.run()` workflow.

### 2026-09-10 ~22:00 UTC — ArmRobot engine mode: full 6D twist + honest orientation state

**Problem.** With a physics engine attached, `ArmRobot.step(u)` consumed only
`u[:3]` (position) — `droll/dpitch/dyaw` were silently dropped, `get_state()`
pinned orientation to `zeros(3)`, and `get_model()` claimed `B = dt·I₆`
(rotational controllability the plant didn't have). The shipped arm scenario
never noticed because `arm_lift.toml` used zero rotation everywhere. A second
silent trap: `iter_phase_schedule` injected the jaw setpoint into `arm_twist[5]`
— which engine mode dropped — so the gripper never moved and
`test_gripper_closes_and_reopens` passed vacuously (asserting schedule values,
not gripper state).

**Fix (TDD, no branch).**
- `PhysicsEngine` ABC + `MuJoCoEngine`: new `get_body_xquat(name)` primitive
  (w,x,y,z) — the missing orientation read.
- `ArmRobot`: `_quat_to_euler_zyx` (ZYX, matching `_pose_to_transform`),
  `_get_ee_euler`, `_orientation_error` (world-frame log map of
  `R_target·R_currentᵀ`, same convention as standalone IK). `step()` now always
  integrates the full 6D twist (`target_euler = current_euler + dt·u[3:6]`) and
  runs 6D damped-LS `engine_ik` on the full 6×k Jacobian (previously sliced to
  `[:3,:]`). Translation-only commands hold orientation (target_euler =
  current_euler) — the old 3D path let the arm reconfigure freely, causing up
  to 0.9 rad of orientation drift on a pure translation. `get_state()` and
  `physics_engine()` attach now report real orientation.
- `iter_phase_schedule`: jaw driven explicitly via
  `engine.set_joint_ctrl(jaw_joint, setpoint)` (`[plant].jaw_joint`, default
  `"Jaw"`) after the arm step — no longer overloads twist channel 5.
- `arm_lift.toml` (now a test fixture after the config cleanup): all waypoints
  seeded with the home EE orientation (roll ≈ 2.0071 rad, read from MuJoCo at
  home qpos) — otherwise the honest state would make the PID fight a 115°
  orientation error and blow the steady-state tolerance.

**Verification.**
- New unit tests: quat↔Euler (vs scipy rotation matrices), orientation error,
  6D `engine_ik` convergence against a faithful mock engine (arm's own
  FK/Jacobian), honest `get_state`, 6D-vs-hold path selection, explicit jaw
  drive. 78/78 `test_armrobot.py`, 89/89 with `test_scenario_run.py`.
- Integration: `arm_cartesian` (steady_state 0.028 < 0.05, estimator 0.009 <
  0.03) and `pick_and_place` (gripper test now asserts real jaw qpos motion,
  range ~3.2 rad) all pass.
- Live sim sweep: pure translation holds orientation (Δeuler ≈ 0 vs 0.91 rad
  before); roll/yaw/pitch each track the commanded rate exactly; full 6D twist
  tracks all six channels.
- `make test`: 1105 passed, 5 skipped, 96 deselected. `make lint` clean
  (ruff + pyright 0 errors).

**Design notes.** Euler-rate integration (not quaternion) keeps engine mode
byte-consistent with the standalone `state += dt·u` math and the documented ZYX
convention; gimbal lock is a documented limitation. `engine_ik` keeps its 3D
path when `target_euler=None` (backward-compatible API), but `step()` always
passes orientation. No codegen impact — plants are never traced; the compiled
graphs (base KF+LQR/KF+MPC) are untouched.
