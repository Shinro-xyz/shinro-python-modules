### 2026-09-10 19:23 UTC — update

**Strict config dataclasses for LQR / PID / MPC (DX audit follow-up).**

Started from a DX audit of the package from an external user's perspective. The
first concrete change: replace the raw-dict `from_config` path for the three
most-used controllers with strict, typed config dataclasses that parse TOML
directly, so authoring typos surface at parse time instead of mid-simulation.

What was built:

- **`src/shinro/utils/config_spec.py`** (new) — `strict_from_dict` / `config_from_toml`.
  A config dataclass's fields ARE the schema: unknown keys, a mismatched `type`
  key, and missing required fields all raise `ValueError` naming the component
  and listing valid keys. `type` is validated against the registered name and
  dropped (absent `type` is fine — MCP inline params don't carry it).
- **`LQRConfig`** (lqr.py) — `state_cost`/`control_cost` required; `dt`,
  `A_dynamics`, `B_dynamics` optional (None = plant-derived in scenario builds).
  Fixed the eager-default bug: `config.get("B_dynamics", config["dt"] * eye(n))`
  evaluated `config["dt"]` even when `B_dynamics` was present, so `dt` could
  never be omitted. Now lazy, with a clear error when neither is supplied
  standalone.
- **`PIDConfig` + `LimitsConfig`** (pid.py) — gains keep their existing defaults
  (kp→[1.0], ki/kd→zeros) so the MCP server's inline-params path and the suite
  stay green; `output_limits` nested table is strict-parsed recursively. `dt`
  required at runtime with an error that teaches the plant-injection rule.
- **`MPCConfig` / `MPCDeltaUConfig` / `ConstraintsConfig`** (mpc_lti.py) —
  `horizon`/`state_cost`/`control_cost` required, `terminal_cost` defaults to
  `state_cost`, `constraints` nested table strict-parsed. `MPCDeltaUConfig`
  subclasses `MPCConfig` via `kw_only=True` (sidesteps dataclass field-ordering),
  so `delta_u_penalty` is required for DeltaU and rejected as unknown for plain
  MPC_LTI.
- Each controller exposes `Config = <...>Config` for discoverability.
- `from_config` still accepts raw dicts (the `isinstance(config, dict)` shim),
  so factories, codegen (`build_composed_graph`), and MCP are untouched.

Design decisions:

- TOML stays the only authoring surface; the dataclass is the parser, not a
  parallel representation. Provenance still hashes raw file bytes.
- `dt`/`A_dynamics`/`B_dynamics` optional-with-None is the seam for the planned
  plant-derived injection (`inject_dt`/`inject_model` via `dataclasses.replace`)
  — not wired yet, that's the next step.
- PID gains kept optional deliberately: the strictness win is rejecting unknown
  keys and wrong `type`, not forcing gains that have a sane P-controller default.

Test changes:

- `tests/test_factories.py::test_create_missing_required_key` — now expects
  `ValueError` (with the missing key named) instead of bare `KeyError`.

Verification:

- `make test`: 1055 passed, 5 skipped, 96 deselected (integration/mcp markers).
- `make lint`: ruff clean, pyright 0 errors on the scoped dirs.
- Smoke-tested the three error classes (typo / wrong type / missing required)
  and the `config_from_toml` path against `lqr_cartpole.toml`.

Next steps (not done): plant-derived `dt`/model injection via `dataclasses.replace`
in `ScenarioFactory._create_loop_role` and `gen_scenario`; add the plant config to
`_provenance`; cookie-cut the remaining controllers/estimators/trajectories onto
the same pattern; `Scenario.run()` public API.
