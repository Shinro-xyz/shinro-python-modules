### 2026-09-10 19:23 UTC — update

**Strict config dataclasses for LQR / PID / MPC (DX audit follow-up).**

Started from a DX audit of the package from an external user's perspective. The
first concrete change: replace the raw-dict `from_config` path for the three
most-used controllers with strict, typed config dataclasses that parse TOML
directly, so authoring typos surface at parse time instead of mid-simulation.

What was built:

- **`src/shinro/utils/config_spec.py`** (new) — `strict_from_dict` / `config_from_toml`.
  A config dataclass's fields ARE the schema: unknown keys, a mismatched `type`
  key, and missing required fields all raise `ValueError` naming the component
  and listing valid keys. `type` is validated against the registered name and
  dropped (absent `type` is fine — MCP inline params don't carry it).
- **`LQRConfig`** (lqr.py) — `state_cost`/`control_cost` required; `dt`,
  `A_dynamics`, `B_dynamics` optional (None = plant-derived in scenario builds).
  Fixed the eager-default bug: `config.get("B_dynamics", config["dt"] * eye(n))`
  evaluated `config["dt"]` even when `B_dynamics` was present, so `dt` could
  never be omitted. Now lazy, with a clear error when neither is supplied
  standalone.
- **`PIDConfig` + `LimitsConfig`** (pid.py) — gains keep their existing defaults
  (kp→[1.0], ki/kd→zeros) so the MCP server's inline-params path and the suite
  stay green; `output_limits` nested table is strict-parsed recursively. `dt`
  required at runtime with an error that teaches the plant-injection rule.
- **`MPCConfig` / `MPCDeltaUConfig` / `ConstraintsConfig`** (mpc_lti.py) —
  `horizon`/`state_cost`/`control_cost` required, `terminal_cost` defaults to
  `state_cost`, `constraints` nested table strict-parsed. `MPCDeltaUConfig`
  subclasses `MPCConfig` via `kw_only=True` (sidesteps dataclass field-ordering),
  so `delta_u_penalty` is required for DeltaU and rejected as unknown for plain
  MPC_LTI.
- Each controller exposes `Config = <...>Config` for discoverability.
- `from_config` still accepts raw dicts (the `isinstance(config, dict)` shim),
  so factories, codegen (`build_composed_graph`), and MCP are untouched.

Design decisions:

- TOML stays the only authoring surface; the dataclass is the parser, not a
  parallel representation. Provenance still hashes raw file bytes.
- `dt`/`A_dynamics`/`B_dynamics` optional-with-None is the seam for the planned
  plant-derived injection (`inject_dt`/`inject_model` via `dataclasses.replace`)
  — not wired yet, that's the next step.
- PID gains kept optional deliberately: the strictness win is rejecting unknown
  keys and wrong `type`, not forcing gains that have a sane P-controller default.

Test changes:

- `tests/test_factories.py::test_create_missing_required_key` — now expects
  `ValueError` (with the missing key named) instead of bare `KeyError`.

Verification:

- `make test`: 1055 passed, 5 skipped, 96 deselected (integration/mcp markers).
- `make lint`: ruff clean, pyright 0 errors on the scoped dirs.
- Smoke-tested the three error classes (typo / wrong type / missing required)
  and the `config_from_toml` path against `lqr_cartpole.toml`.

Next steps (not done): plant-derived `dt`/model injection via `dataclasses.replace`
in `ScenarioFactory._create_loop_role` and `gen_scenario`; add the plant config to
`_provenance`; cookie-cut the remaining controllers/estimators/trajectories onto
the same pattern; `Scenario.run()` public API.

### 2026-09-10 19:51 UTC — update

**ConfigDriven ABC mixin + Tier-1 cookie-cut (estimators + remaining loop controllers).**

Extended the strict-config pattern from three controllers to the whole
control loop, with framework-level enforcement so new components are forced
to declare their schema.

What was built:

- **`ConfigDriven` mixin** (components.py) — `Config: ClassVar` + `parse_config`
  classmethod that strict-parses a TOML dict into `cls.Config` using the
  component's registry name (fallback: class name for unregistered bases).
  Applied to `Controller` and `StateEstimator` ABCs (`PhysicsEngine` excluded —
  engines are constructed directly). LQR/PID/MPC `from_config` refactored to the
  one-line `cls.parse_config(config)` idiom; nested-table parses (LimitsConfig,
  ConstraintsConfig) keep using `strict_from_dict` directly.
- **Estimators cookie-cut (enforced)**: `KalmanFilterConfig`, `LuenbergerObserverConfig`
  — process_noise/measurement_noise or observer_gain required; dt/A/B/C/D optional
  with lazy defaults. Both had the eager-`config["dt"]` bug (KeyError even when
  `B_dynamics` present) — fixed.
- **Controllers cookie-cut (warned)**: `SMCConfig` (c, k1 required; phi/k2/smoother/
  alpha optional; dt accepted-but-unused for TOML compat), `MPPIConfig`
  (num_samples/temperature/horizon/noise_sigma required; dt optional-with-runtime
  error like PID; state_cost/control_cost as TOML-authorable fields; dynamics_fn/
  cost_fn deliberately NOT in the schema — they're runtime-injected callables).
- **Registry enforcement** (factories/registry.py): `_check_config` helper;
  `register_estimator` raises `TypeError` at import (both estimators migrated);
  `register_controller` emits a `UserWarning` naming the class and pointing at
  LQRConfig — fires only for `onnx_rl`/`lerobot_diffusion` (pending rewrite:
  their NN runtimes are untraceable to the codegen VM and will be rewritten,
  at which point this flips to strict).

Design notes:

- Non-TOML values (MPPI callables, engine handles) are deliberately outside the
  schema — the dataclass declares only what's authorable in TOML; from_config
  handles runtime injection. This forces the config-vs-injected boundary to be explicit.
- MPPI/SMC/estimators all follow the LQR template: required fields strict,
  `dt`/`A_dynamics`/`B_dynamics` optional-None as the seam for the future
  plant-derived injection.

Tests: added `TestRegistryConfigEnforcement` in test_factories.py (estimator
without Config raises; controller without Config warns + registers; all built-in
estimators + loop controllers assert Config present). One pre-existing test
updated: missing-required-key now `ValueError` (from the earlier pass).

Verification: `make test` 1058 passed, 5 skipped; `make lint` ruff + pyright clean.
Smoke-checked: import surfaces exactly the two expected warnings (lerobot_diffusion,
onnx_rl); `config_from_toml(KalmanFilterConfig, ...)` round-trips.

Remaining: plants + trajectories cookie-cut + enforcement; OnnxRL/LeRobot rewrite
(flips register_controller to strict); plant-derived dt injection via
`dataclasses.replace`; `Scenario.run()`.

### 2026-09-10 20:21 UTC — update

**Plants + trajectories cookie-cut; every registry now enforced (except controllers).**

Completed the strict-config migration: all 6 plants and all 4 trajectory types
now have Config dataclasses, and `register_plant` / `register_trajectory` flipped
to strict (TypeError at import for a Config-less component). Only the two
pending-rewrite NN adapters (`onnx_rl`, `lerobot_diffusion`) remain on warnings.

Plants:

- `InvertedPendulumConfig`, `CartPoleConfig`, `DoublePendulumConfig` — every
  physical parameter has its current default, so the plant TOML stays the single
  source of physics truth with a minimal `type` + `name` config. Nested
  `[state_bounds]` strict-parsed via the shared `BoundsConfig` (min/max optional,
  per-plant defaults preserved).
- `HolonomicMobileRobotConfig` — geometry + dt required.
- `ArmRobotConfig` — num_dof/joint_group/joint_offsets/rot_axes/dt required,
  ee_body_name optional; `joint_groups` (the lookup table) and `engine` are
  runtime-injected by RobotSim and stripped before parsing, with a loud error
  when missing (ArmRobot is sim-only by construction).
- `QuadrotorConfig` — schema-only placeholder documenting the intended 12D/4D
  surface; construction still raises NotImplementedError.
- New `strip_runtime_keys` helper (config_spec.py): pops RobotSim-injected
  `engine` + `joint_groups` from the merged plant config dict before strict
  parsing. **Caught a real bug pre-CI:** my first pass stripped `engine` only,
  and 13 integration tests failed on `unknown key(s) ['joint_groups']` —
  robotsim.py:60 merges `joint_groups` into *every* plant config, not just
  ArmRobot's. All plants now strip both.

Trajectories:

- Nested entry schemas: `CubicSegmentConfig`, `QuinticSegmentConfig`,
  `WaypointConfig`, `PhaseConfig` — each `[[segments]]`/`[[waypoints]]`/
  `[[phases]]` entry is strict-parsed via the new `strict_from_list` helper,
  so a typo'd key inside a segment entry names the trajectory and entry type.
- `CubicSegmentsConfig` / `QuinticSegmentsConfig` / `WaypointsConfig` /
  `PhasesConfig` as the top-level schemas; adapter/standalone classes
  (`QuinticPolynomialConfigAdapter`, `WaypointSchedule`, `PhaseSchedule`) now
  inherit `ConfigDriven` directly (they never extended the ABC).
- Behavior fix along the way: omitted `start_vel`/`end_vel`/acc defaults were
  hardcoded `[0.0, 0.0, 0.0]` — wrong for non-3D trajectories (latent shape bug).
  Now zeros matching the segment's start length (identical for 3D).
- `QuinticPolynomial` (the math class, registered then overwritten by the
  adapter under the same name) got a schema-only Config so strict registration
  passes.

Enforcement: `register_plant` + `register_trajectory` strict; added
`test_registered_plants_and_trajectories_all_have_config`,
`test_register_plant_without_config_raises`, and
`test_register_trajectory_without_config_raises`.

Verification: `make test` 1061 passed; full integration suite 58 passed
(covered the engine/joint_groups stripping on every sim-backed path); `make
lint` ruff + pyright clean.

Remaining: OnnxRL/LeRobot rewrite (flips register_controller to strict);
plant-derived dt/model injection via `dataclasses.replace`;
`Scenario.run()` public API.

### 2026-09-10 20:50 UTC — update

**Plant-derived dt/model injection — the plant TOML is now the single source of physics truth everywhere.**

Closed the loop on the dt duplication: controller/estimator configs no longer
need to restate `dt` (or the model) in any scenario-driven build. Precedence:
**explicit wins, derived fills, disagreement is loud.**

What was built:

- **`inject_plant_derived(cfg, plant, *, with_model)`** (linearization.py) —
  operates on Config dataclass instances via `dataclasses.replace`: fills `dt`
  from `plant.dt` when omitted, raises a loud `ValueError` on disagreement
  (a mismatched PID/MPPI dt silently mis-scales integration — now impossible),
  and with `with_model` derives `A_dynamics`/`B_dynamics` via `derive_model`
  when the config declares neither (injected as TOML-serializable lists so the
  resolved config stays serializable). The `with_model` kwarg name avoids
  shadowing the module-level `derive_model` function (caught by the new tests).
- **`ConfigDriven.load_config(config, plant=None, derive_model=False)`**
  (components.py) — strict-parse (TOML path or dict) → injection. This is the
  one injection seam; the dict-level `inject_model` remains for backward compat.
- **Factories**: `ControllerFactory.create(backend, plant, derive_model)` and
  the Estimator twin. `ScenarioFactory._create_loop_role` now just passes
  `plant` through. Semantics: dt fill+disagreement-check applies in **both**
  sim-backed and plant-only modes (all shipped sim configs agree at 0.02);
  model derivation only in plant-only mode, preserving the "sim-backed
  velocity-commanded defaults untouched" contract.
- **Compile path** (scenario_gen): resolves the estimator/controller registry
  classes (type read from the scenario TOML, or from the component's own TOML
  when the scenario omits it), runs `load_config(..., plant, derive_model=True)`,
  and flattens back to the dict shape `build_composed_graph` dispatches on.
- **Provenance**: `_provenance` now hashes the plant config TOML when
  derivation was used — the master build hash commits to every input file.
- **Shipped e2e regression**: stripped `dt` from `lqr_cartpole.toml`,
  `kalman_cartpole.toml`, and `luenberger_cartpole.toml` — these are shared by
  the plant-only sim scenario (cartpole_balance) and the derived compile
  scenario (cartpole_lqr_kf_derived), so both pipelines now prove injection.
  The estimator parity guard was updated to allow dt-less (plant-inherited)
  twin pairs.

Test fallout caught real integration issues immediately: `test_compile_scenario`'s
fixture TOMLs omit `type` in [controller]/[estimator] (only a config path) — the
type is now derived from the component file when the scenario doesn't declare it.

New tests (test_codegen_build.py): `TestInjectPlantDerived` (dt filled from
plant, matching dt left alone, mismatch loud, explicit A blocks model injection,
PID's missing A/B fields skipped) and `TestLoadConfigPlantInjection` (shipped
dt-less lqr_cartpole.toml builds via plant path; factory `create(plant=...)`
produces the plant-derived A/B).

Verification: `make test` 1068 passed; integration 58 passed; `make lint`
ruff + pyright clean.

Remaining: OnnxRL/LeRobot rewrite (flips register_controller to strict);
`Scenario.run()` public API (the replace-based config flow now exists to
support it).
