### 2026-09-08 23:45 UTC — cross-compile skips the host oracle

**What:** `build_scenario.py` now gates the oracle on the resolved target. For
non-native targets (e.g. `--target aarch64-linux-gnu` for a Raspberry Pi) the
host oracle is skipped, while the integrity check, stamp, and verify still run.

**Why:** cross-compiling previously died at the oracle step with a misleading
`OSError: ... cannot open shared object file: No such file or directory` — the
`.so` was built fine, but `ctypes.CDLL` can't dlopen a foreign-arch ELF on the
host. The oracle is the only host-bound step in the pipeline; gen, integrity
check, `zig build`, stamp, and verify are all target-agnostic.

**Design decision:** Level 0 gate (`if tgt == "native":`) rather than a full
arch-comparison table. `"native"` is the only case where the host is guaranteed
to run the binary; any explicit triple skips the oracle. A Level 1 arch-compare
(host `platform.machine()` vs target prefix) was considered and deferred — it
only adds value for the edge case of pinning the host's own triple in the TOML.
Skipping the oracle moves the numeric cross-check to the device (the on-Pi
driver should compare against a known-good vector baked from `interpret()`).

**Files:**
- `src/shinro/codegen/scenario_build.py` — oracle wrapped in `if tgt == "native":`,
  else-branch prints a skip note; module docstring updated.
- `tests/test_compile_scenario.py` — added `test_e2e_cross_compile_skips_oracle`
  (zig-gated): cross-build exits 0, prints the skip note, no "oracle B", `.so` +
  deployment record produced.

**Test results:** `tests/test_compile_scenario.py` 10/10 pass (native oracle
test still asserts "oracle B"; new cross-compile test asserts it's skipped).
`ruff check` clean on both changed files. Verified manually: `make compile
... FLAGS="--target aarch64-linux-gnu"` now completes end-to-end (gen →
integrity → cross-build → stamp → verify, exit 0).
