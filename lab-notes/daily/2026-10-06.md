# 2026-10-06 — Unscented Kalman filter: sigma-point predict/update, TOML config, tests

Branch: `feat/estimator-additions`

## Why

`src/shinro/estimators/unscented_kf.py` was a work-in-progress stub: it carried
`@register_estimator("UnscentedKF")` but no frozen `Config`, so the strict
estimator registry raised `TypeError` at import, and `estimate()` stopped after
the first sigma-point line. This slices the UKF into the same shape as the EKF
on this branch: full predict/update math, strict TOML config, a
`from_config` + reset, re-export, and a numpy/torch test class.

## The error surface found while fixing it

The stub had a mix of hard and silent bugs:

- **Syntax:** `w_covar =` with no RHS (the user had already patched it).
- **Off-by-one:** weight arrays sized `2*nx`, but the loop writes indices
  `1..2*nx` — must be `2*nx + 1` (the mean point plus `2n` spread points).
- **Ordering:** `_weights_sigmapoints` referenced `self.lamb`, which was only set
  inside `_sigma_points`; because `__init__` calls the weight builder first, it
  raised `AttributeError` at construction.
- **Coupling:** `_sigma_points` read `self.P` implicitly, so the measurement
  update could not draw points from the *predicted* `(x_pred, P_pred)`. It now
  takes `(x, P)` as arguments.
- **Registry:** the estimator registry is `strict=True` (unlike controllers), so
  a frozen `UnscentedKFConfig` dataclass is mandatory — its absence made the
  module unimportable.
- **Factory:** `EstimatorFactory` calls `cls.from_config(...)`, so that had to be
  added, not just `Config`.

## Math / convention decisions

- **Continuous-time process model**, the same contract as the EKF:
  `dynamics_fn(x, u) -> dx/dt`, Euler-stepped once per tick as
  `chi_pred = chi + dt * f(chi, u)`. This keeps UKF/EKF swappable in a scenario.
- **Flat vectors throughout** — state `(n_x,)`, control `(n_u,)`, measurement
  `(n_y,)` — matching the EKF (the discrete `KalmanFilter`/`LuenbergerObserver`
  use columns instead; the UKF deliberately follows EKF).
- **Standard scaled UT weights** with the usual `lambda = alpha^2 (n + kappa) - n`,
  `W0_mean = lambda/(n+lambda)`, `W0_cov = W0_mean + (1 - alpha^2 + beta)`, and
  `Wi = 1/(2(n+lambda))`. `Config` defaults are `alpha=1e-3, beta=2, kappa=0`.
- **Redraw sigma points around the prediction** for the measurement update
  (rather than reusing the propagated set) — the standard Wan/van der Merwe form.
- The update uses the simple `P = P_pred - K S K^T` form (not Joseph), matching
  the KF/EKF style.

### The reshape that makes the weights work

`w_mean`/`w_covar` are `(L,)` with `L = 2n+1`; point stacks are `(L, d)`.
A bare `w * points` right-aligns trailing axes and would line `L` up against the
columns, so the weights are reshaped to a column `(L, 1)`: that broadcasts to
`(L, d)` and scales **each point row** by its weight. `bk.sum(..., axis=0)`
then gives the weighted mean; `(w*d).T @ d` and `(w*dx).T @ dz` give the
covariance and cross-covariance as sums of weighted outer products.

## The test that caught a real bug

`test_accepts_column_vector_measurement` failed on **both** backends: the UKF
passed `control_input` through raw, so a column `u` of shape `(n_u,1)` made
`Bc @ u` `(n_x,1)`, broadcast against `Ac @ x` `(n_x,)` into an `(n_x,n_x)`
result, and the sigma-point assignment then failed. Fixed by flattening
`u`/`z` and each model output with `bk.ravel` — the same robustness the EKF
gets from its `_flat` helper.

## 2026-10-06 (later) — UKF `attach_plant` + linear `measurement_matrix`, and a shared model-call helper

### Why

The first UKF slice left two gaps that the EKF already closes: a config-only UKF
could not get a measurement model, and a plant could not supply its process
model. Both are the same pattern the EKF uses, so they were copied over — which
surfaced one shared helper worth extracting.

### What changed

- **`src/shinro/estimators/model_call.py` (new).** `accepts_backend(fn)` and
  `call_model(fn, *args, bk=...)` were living privately in `extended_kf.py`.
  `attach_plant` makes the UKF call `Plant.dynamics`, which takes an optional

  numpy plant otherwise mis-resolves). Rather than duplicate the helper, it moved
  to a shared module and `extended_kf.py` now imports it (its private

- **UKF `measurement_matrix`** — optional linear `C`, stored as `self.C` with the

- **UKF `attach_plant(plant)`** — fills an **unset** `dynamics_fn` from
  `plant.dynamics` (explicit injection wins); a plant with no `dynamics` and a

- **Config** gains `measurement_matrix`, carried through `from_config`.

## 2026-10-06 (later still) — Sigma points as a batch (eager) + a `concat` backend op

### Why

Batching the sigma points is not just a speedup: the tracing backend's
`Tracer` has no `__getitem__`, so the per-point index-assignment loop **cannot
lower at all**. A single batched `f(chi, u)` lowers as one `f` subgraph, the
same trick the EKF's batched finite-difference Jacobian uses. This slice does
the *eager* batched + trace-friendly shaping; the actual lowering still needs a
Cholesky VM op (see Remaining).

### What changed

- **`utils/array_backend.py`** — added `concat(arrays, *, axis=0)` to the ABC,
  `NumpyBackend` (`np.concatenate`) and `TorchBackend` (`torch.cat`), matching
  `TraceBackend.concat`'s signature (which already existed). Needed because the
  trace-friendly sigma-point build uses concat, and the eager backends lacked it.
- **`estimators/unscented_kf.py`**
  - `_sigma_points` is now built by concat — `chol.T`, `-chol.T`, broadcast add,
    `concat` — with **no index assignment**, so the construction is traceable.
  - `_weighted_mean` is a matmul `w(1,L) @ points(L,d)` instead of
    `sum(..., axis=0)` (`sum` is not a VM op); bit-identical to the reduction.
  - `_dynamics_batch` / `_measurement_batch` evaluate the whole `(L, n)` batch in
    one call when the model is batch-capable, else fall back to row-by-row.
  - `_batchable(fn)` = auto-detect via `accepts_backend` (plants/compiled models
    accept `bk` **and** the `(N,n)` batch contract), with a `batched` constructor
    kwarg to force either path (`batched=False` is the escape hatch).
  - `estimate` predict/update per-point loops are gone — one batched call each.

### Equivalence (measured)

- concat sigma points == index-assignment loop: **maxΔ 0.0**
- batched plant predict == per-point loop: **maxΔ 0.0**
- matmul mean == `sum(axis=0)`: exact
- `test_batched_and_per_point_paths_agree` (CartPole + identity `C`, 5 steps):
  batched vs forced-loop identical to `1e-12` (actually 0.0).

### Tests

- `tests/test_estimators.py` — `test_auto_batching_detects_bk_aware_models`,

## 2026-10-06 (night) — Cholesky kernel + VM op: the last gate to lowering the UKF

### Why

The UKF's batched / trace-friendly rewrite left exactly one op missing from the
VM: a matrix square root. This slice adds the kernel and wires it end-to-end
(the `wire-linalg-kernel` checklist), so a UKF graph can now compose and lower.

### What was built

- **`runtime/linalg.zig`** — `cholesky(comptime n, a)`: lower-triangular `L` with
  `L @ L.T == a`. The first draft read the **original** matrix in the
  accumulation instead of the already-computed factor (`sum -= a[i][k]*a[j][k]`),
  which produced `NaN` on a non-trivial off-diagonal; fixed to read `out[...]`.
  Verified against hand-computed 2×2 (`[[4,2],[2,3]] → [[2,0],[1,√2]]`) and 3×3
  integer factors.
- **`codegen/ops.py`** — `@register_op("cholesky")`, the numpy oracle
  (`np.linalg.cholesky`).
- **`codegen/trace_backend.py`** — `TraceBackend.cholesky`, emitting

- **`codegen/lower_zig.py`** — `cholesky` added to the emitted `Op` enum; it has
  no attrs, so it maps to itself via the default `(op, 0)`.
- **`runtime/lower.zig`** — the `.cholesky` VM arm beside `.inv`, with a comptime
  gate rejecting non-square / 1-D operands.
- **Frozen fixture graphs** — regenerated with `scripts/gen_lower_fixtures.py`

  one line (`cholesky,`); weight `.bin`s and oracle vectors came back

## 2026-10-06 (later) — UKF trace-safety: the sigma points now compile

### Why

With `cholesky` wired, the only thing between the UKF and a `.so` was its own
**trace-safety**. `estimate` used two numpy-only idioms the `Tracer` rejects, so
it failed at *trace* time (before lowering) and neither a standalone nor a
composed UKF graph could be built.

### What changed (`estimators/unscented_kf.py`)

- **`_weighted_mean`** — reshape the baked weights on the array
  (`w_mean.reshape(1, L)`), not via `bk.reshape`. During tracing `self.bk` is the
  `TraceBackend`, which expects a `Tracer` and cannot infer a `-1`; reshaping the
  numpy/torch array itself leaves it liftable to a **`const`** node via
  `Tracer.__rmatmul__` (`w @ points`).
- **`_weighted_cov` / `_cross_cov`** — lift each rank-1 mean to a `(1, d)` row
  (`self.bk.reshape(mean, (1, points.shape[1]))`) before subtracting. The tracer
  enforces matching ranks (no rank-2 minus rank-1 broadcast).
- All three are **behavior-preserving in eager mode** (identical arithmetic), so
  the existing UKF tests pass unchanged.

### Measured (once traced)

- UKF **glue** = **75** ops, constant in `n_x`.
- UKF estimator = 75 + |plant f-subgraph|: **CartPole (4,4) 129**, **Quadrotor (12,4) 242**.
- Full composed **UKF+CartPole+LQR = 136**, **UKF+Quadrotor+LQR = 249**.
- vs EKF estimator (same plants): **164** / **390** — the EKF emits the plant
  **twice** (f + FD Jacobian); the UKF once, batched.
- `.so` oracle parity vs `interpret()`: **0.0** (exact), composed CartPole graph.

### Tests

`tests/test_codegen.py` — `TestTraceUnscentedKF`: the interpreted UKF graph ==
`NumpyBackend` UKF on 20 random inputs (`atol 1e-10`), plus the op/state capture
(`cholesky`/`concat`/`matmul`/`inv`; `x_hat`/`P` as state).

## 2026-10-06 (late) — UKF scenario: gate A + oracle B on the compiled sigma-point graph

### Note on partial measurement

The `y` port width comes from `compose._measurement_dim`, which reads the
estimator's `n_y` or, failing that, its `C` row count. The UKF names its dims
`nx`/`ny` (not `n_y`), but it exposes `self.C` when `measurement_matrix` is set,
so the partial `n_y < n_x` case composes correctly.
