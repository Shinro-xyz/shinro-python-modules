### 2026-09-11 18:32 UTC — unified oracle pipeline (oracle.py + parameterized closed-loop driver)

**What:** Consolidated the `.so`-vs-numpy oracle machinery — previously implemented three times (product `scenario_build.py`, the pytest suite, and mirrored in shinro-bench's fidelity payload builder) — into one module, `src/shinro/codegen/oracle.py`. Also collapsed the five bespoke 100-tick closed-loop oracle test classes in `tests/test_zig_lowering.py` into one declarative table + generic driver.

**Why:** The comparison conventions (seeded random inputs with SPD square-2D ports, flat C-ABI packing, per-port max-abs error, QP/non-QP tolerance tier `TOL_QP=1e-3` / `TOL_NON_QP=1e-12`) are exactly the things that silently invalidate an oracle if three copies drift. Now one home; the build-time gate, CI, and (later) on-target verification provably run the same check. Tests now exercise the product's own oracle code, so a bug in `compare_ports` fails the suite instead of silently invalidating everything downstream.

**oracle.py API** (promoted from scenario_build, semantics byte-identical): `input_shape`, `output_shape`, `output_size`, `output_split`, `state_slices`, `pack_arrays`, `random_inputs`, `load_so`, `step_so` (dropped the unused `cg` param — ~20 call sites updated across three test files), `compare_ports`, `run_oracle`, `tol_for`. `scenario_build.py` keeps the `[compile].oracle_tol` override layered on `tol_for(manifest)`; `scripts/build_scenario.py` shim re-exports the TOL constants from oracle.

**Closed-loop driver:** `ClosedLoopCase` dataclass (fixture name, estimator/controller factories, `mode` ∈ tracking/error/error_deltau, `est_state_ports` port↔attr map, `est_seed_mode` cross/self, `ctrl_state_ports`, `est_init`, tol, seed, `sat_threshold`) — five cases preserving the original per-case seeds (11/21/31/37/41), tolerances (1e-10 / 1e-4), and semantics. Design decision preserved from the originals: KF cases "cross"-seed the live estimator from the .so's threaded state each tick (isolates single-tick predict-update fidelity from drift accumulation toward the gate), while Luenberger runs "self"-seeded (both sides evolve independently — the stronger property, and the estimator-swap regression). PID keeps the `saw_saturation` guard (sat_threshold=0.3) so the anti-windup ne/where path must genuinely fire.

**Bench (deferred, then reverted):** I updated shinro-bench's `fidelity_prep.py` / `cartpole_deploy.py` / `test_fidelity_closed_loop.py` to the oracle API; a concurrent agent committed those edits (`1bccf9f`, `7f74bb0`). The bench is **pinned to the shinro 0.2.2 wheel** (user decision), where `oracle.py` doesn't exist — so I reset those two commits and restored the bench to its pre-edit state (verified: collection green against the wheel). Left behind: untracked `shinro-bench/configs/controllers/mpc_lti_{cartpole,inverted_pendulum,double_pendulum}.toml` restored from git history (`afc13a7^`) — inert against the pinned wheel (packaged configs win resolve order) but they fix the 6 pre-existing config-resolution errors that will appear the moment the wheel is refreshed from current source. Bench-side unification is designed and re-appliable in minutes after a wheel refresh.

**Verification:** `make test-zig` 52/52 (incl. all 5 closed-loop cases); full `make test` 1105 passed / 5 skipped / 96 deselected — identical to baseline (5 test methods removed, 5 parametrized cases added, net zero); `make lint` (ruff + pyright) clean; `make zig-gen` re-run, shipped KF+LQR graph restored. Nothing committed.

### 2026-09-11 21:23 UTC — de-LeKiwi RobotSim: post_engine_step hook

**What:** Removed all LeKiwi-specific logic from `RobotSim.step()`. Added a concrete no-op `post_engine_step(engine)` hook on the `Plant` ABC ([components.py]); `RobotSim.step()` is now just `engine.step()` + the hook for each plant. `HolonomicMobileRobot` implements the hook: it syncs the engine's free-joint chassis pose from the plant's kinematically integrated state (quaternion pinned upright, floating-base qvel zeroed), then deposits `_target_wheel_delta` onto the drive joints for visual rolling. `drive_joints` is now an explicit field on `HolonomicMobileRobotConfig` (strict schema), falling back to the sim-level `[joint_groups].drive_joints` table RobotSim injects — so a plant TOML can declare it directly, or the sim wiring supplies it. Also added a public `RobotSim.plants` property, replacing the `sim._plants` private reach in `scenario_factory.py`.

**Key behavior change (intentional):** the old guard `hasattr(self, "base")` meant the sync silently skipped when a self-integrating base plant wasn't *named* "base" (the chassis then free-falls under gravity in the sim). The hook now fires based on engine capability (`has_free_joint`), not plant naming. Verified with a minimal free-joint MJCF fixture: old code drifted (chassis z fell to −0.116); new code syncs pose regardless of plant name.

**Bit-exactness:** compared HEAD~ robotsim.py against the new implementation on (a) the shipped LeKiwi config (no free joint — old block never fired) and (b) the free-joint fixture with plant named "base" (old block active): qpos, qvel, and plant state are byte-identical after 10 steps, including wheel-delta consumption.

**Test results:** full suite — 1032 passed, 5 pre-existing failures (zig build: sandbox root FS is read-only so zig can't write its global cache; pick_and_place fixture was deleted in f7f730e, breaking 8 tests independent of this change). `make test-integration` — 50 passed excluding the same pre-existing fixture/zig failures; `test_base_tracking` (the base-sync oracle) 7/7 in both parent and new trees. `demo_simple` runs cleanly; ruff clean.

### 2026-09-12 00:00 UTC — Stage 4: phase schedules de-LeKiwi'd (generic signal routing)

**What:** Removed every LeKiwi-specific literal from the phase-schedule path. `iter_phase_schedule` is now fully signal-name-driven: a schedule key matching a declared plant name routes to `plant.step(u)`; any other key must be declared in the scenario's `[signals]` table (`name = { actuator = "<actuator>" }`) and routes to `engine.set_joint_ctrl` directly. The old `arm`/`base`/`jaw` literals, the `[plant].jaw_joint` fallback, and the hardcoded `"Jaw"` default are all gone. `PhaseConfig` in `quintic_polynomial.py` changed from the hardcoded `arm`/`base`/`jaw` fields to a generic `signals: dict[str, list[float]]`. Scenario records now carry the full applied signal dict (was: arm/base only, base_state silently discarded).

**Why:** the phase runner was the last LeKiwi-shaped file in the framework — it named the robot's plant roles in code. Now a humanoid manifest with plants `left_arm`/`right_arm`/`torso` and a gripper signal works with zero runner changes, and a renamed LeKiwi (plant "chassis") works identically.

**Loud failures added:** unknown schedule keys → ValueError naming declared plants + signals; `[signals]` actuator missing from the engine → ValueError naming declared actuators; schedule signals with mismatched lengths → ValueError before the loop starts. All are build-time errors per the repo's fail-at-parse philosophy.

**Data migrations:** `tests/integration/scenarios/pick_and_place.toml` gained `[signals] jaw = { actuator = "Jaw" }`; packaged `configs/trajectories/pick_and_place.toml` converted to the `[phases.signals]` form (verified byte-identical behavior by the integration suite).
