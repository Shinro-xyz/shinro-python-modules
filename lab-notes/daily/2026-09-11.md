### 2026-09-11 18:32 UTC — unified oracle pipeline (oracle.py + parameterized closed-loop driver)

**What:** Consolidated the `.so`-vs-numpy oracle machinery — previously implemented three times (product `scenario_build.py`, the pytest suite, and mirrored in shinro-bench's fidelity payload builder) — into one module, `src/shinro/codegen/oracle.py`. Also collapsed the five bespoke 100-tick closed-loop oracle test classes in `tests/test_zig_lowering.py` into one declarative table + generic driver.

**Why:** The comparison conventions (seeded random inputs with SPD square-2D ports, flat C-ABI packing, per-port max-abs error, QP/non-QP tolerance tier `TOL_QP=1e-3` / `TOL_NON_QP=1e-12`) are exactly the things that silently invalidate an oracle if three copies drift. Now one home; the build-time gate, CI, and (later) on-target verification provably run the same check. Tests now exercise the product's own oracle code, so a bug in `compare_ports` fails the suite instead of silently invalidating everything downstream.

**oracle.py API** (promoted from scenario_build, semantics byte-identical): `input_shape`, `output_shape`, `output_size`, `output_split`, `state_slices`, `pack_arrays`, `random_inputs`, `load_so`, `step_so` (dropped the unused `cg` param — ~20 call sites updated across three test files), `compare_ports`, `run_oracle`, `tol_for`. `scenario_build.py` keeps the `[compile].oracle_tol` override layered on `tol_for(manifest)`; `scripts/build_scenario.py` shim re-exports the TOL constants from oracle.

**Closed-loop driver:** `ClosedLoopCase` dataclass (fixture name, estimator/controller factories, `mode` ∈ tracking/error/error_deltau, `est_state_ports` port↔attr map, `est_seed_mode` cross/self, `ctrl_state_ports`, `est_init`, tol, seed, `sat_threshold`) — five cases preserving the original per-case seeds (11/21/31/37/41), tolerances (1e-10 / 1e-4), and semantics. Design decision preserved from the originals: KF cases "cross"-seed the live estimator from the .so's threaded state each tick (isolates single-tick predict-update fidelity from drift accumulation toward the gate), while Luenberger runs "self"-seeded (both sides evolve independently — the stronger property, and the estimator-swap regression). PID keeps the `saw_saturation` guard (sat_threshold=0.3) so the anti-windup ne/where path must genuinely fire.

**Bench (deferred, then reverted):** I updated shinro-bench's `fidelity_prep.py` / `cartpole_deploy.py` / `test_fidelity_closed_loop.py` to the oracle API; a concurrent agent committed those edits (`1bccf9f`, `7f74bb0`). The bench is **pinned to the shinro 0.2.2 wheel** (user decision), where `oracle.py` doesn't exist — so I reset those two commits and restored the bench to its pre-edit state (verified: collection green against the wheel). Left behind: untracked `shinro-bench/configs/controllers/mpc_lti_{cartpole,inverted_pendulum,double_pendulum}.toml` restored from git history (`afc13a7^`) — inert against the pinned wheel (packaged configs win resolve order) but they fix the 6 pre-existing config-resolution errors that will appear the moment the wheel is refreshed from current source.
