# 2026-10-12 — Schema-driven Zig lowering: turnkey op surface for the comptime VM

Branch: `refactor/compiler-consolidation`

## Why

Adding or changing a VM op used to require editing the serializer
(`codegen/lower_zig.py`) in five places: append to the hand-written `Op` enum,
add a parallel f64 table (`gemm_alpha`, `layernorm_eps`, ...), thread that table's
dict through `_node_line` → `_graph_manifest` → both `_node_vm_info` call sites,
and add another branch to `_node_vm_info`'s if-ladder. That is mechanical, easy to
get wrong, and it is the only op surface with drift risk — the reason
`test_drift_guard_nodes_match_emitted_table` exists at all.

The goal of this refactor is **turnkey**: change a kernel and it works out of the
gate, with no hand-maintained serializer coupling. The lowering metadata now
lives next to the numpy oracle, declared once:

```python
@register_op("gemm", vm=VmOp(attrs=(AttrSpec("alpha", 1.0), AttrSpec("beta", 1.0)),
                             flags=("transB",)))
def _gemm(node, values, inputs): ...
```

`lower_zig` derives the enum, the baked `<op>_<attr>` tables, the packed `aux`
word, and the manifest from that registry. Adding a VM op now needs only a
`vm=VmOp(...)` (or nothing, for identity ops) plus a `lower.zig` switch arm — the
serializer is never touched. The `wire-linalg-kernel` skill drops from **six
surfaces to five**.

Framing note: `lower_zig` already emitted data (Zig-source-encoded constants),
never statements; this is an *encoding/ownership* change — the per-op encoding
knowledge moves from the serializer into a declarative schema — not a
"code → data" change.

## What changed

- **`codegen/vm_schema.py`** (new) — `VmOp` / `AttrSpec` dataclasses + registry.
  A `VmOp` declares: the Zig enum name (rename), `attrs` (f64 scalars → one
  `<op>_<attr>` table, shared index in `aux`), `flags` (bool attrs → `aux` bits),
  `array_attrs` (broadcast arrays → `clip`'s `lo`/`hi`), and `slot`
  (`attr:<name>` / `axis_code` / none). `vm_op_name`, `table_names`, and
  `get_vm_op` (identity default) are the accessors.
- **`codegen/ops.py`** — `register_op(name, *, vm: VmOp)` attaches the schema,
  and `vm` is **mandatory** (every one of the 48 registrations declares a
  `VmOp`, including the identity ops as `vm=VmOp()`). Annotated the 15 ops that
  previously had bespoke lowering: `const`/`input`/`output` (renames
  `cst`/`inp`/`out`), `where` (`where_op`), `clip` (array attrs),
  `slice`/`gather`/`concat` (`slot="attr:..."`), `min` (`axis_code`),
  `gemm`/`elu`/`leaky_relu`/`layernorm` (scalar attrs), `gru`/`mod` (flags). The
  serializer can no longer see an op without a schema — there is no identity
  default to fall back to.
- **Schema enforcement** — `register_op` rejects a handler with no `vm=`
  (`TypeError`); `vm_schema.get_vm_op` raises instead of defaulting;
  `vm_schema.missing_schemas()` lets `lower_zig` assert the registry is complete
  before emitting; and `TestVmSchema` covers all three (`declares_a_schema`,
  `requires_a_schema`, enum coverage). The schema set is now provably equal to
  the handler set.
- **`codegen/lower_zig.py`** — rewritten schema-driven. `_node_vm_info`,
  `_node_line`, and the five parallel-table passes are gone; a single
  `_encode_node` produces a `(vm_op, aux)` per node, consumed by both the emitted
  table and the manifest. The `Op` enum is derived from the registry
  (`_op_enum_names`). `const`/`input`/`output` keep a small structural block for
  the blob/input/port offsets (plumbing, not attributes). The two large numeric
  blobs and the f32-weight decision are unchanged.
- **`tests/test_codegen.py`** — new `TestVmSchema`: every registered op maps to a
  valid, non-reserved Zig variant; the renamed/attributed ops are declared; and
  the emitted enum covers every registered op (so an op can't silently drop out).
- **Docs** — `docs/codegen.md` module map + lower step; `runtime/README.md`
  serializer note; `.agents/skills/wire-linalg-kernel/SKILL.md` (six → five
  surfaces, schema step, pitfalls, worked example).

## Design decisions

- **Keep the Zig `Node` struct and ABI fixed.** The tempting alternative was to
  replace `aux` with generic `attrs`/`flags`/`slot` fields, but `lower.zig` arms,
  the frozen fixture graphs (`runtime/tests/graphs/*.zig` each re-declare `Node`
  exactly), and the C-ABI all depend on the current record. Encoding the schema
  into the *existing* `aux` + per-op table names (`aux = (index << nflags) |
  flagbits` for attrs+flags; `aux = flagbits` for flags-only; `aux = slot` for
  selectors) keeps the whole runtime, all fixtures, and the drift guard untouched
  — the refactor is Python-only.
- **`aux` packing is byte-for-byte the old scheme** (`gemm`: `(idx<<1)|transB`,
  read as `[aux/2]`), so node encodings reproduce exactly and the manifest is
  semantically identical.
- **Enum is derived, not hand-listed.** Order changes (register order vs. the old
  hand order) but Zig references variants by name and the drift guard parses
  nodes, not the enum, so this is cosmetic. Accepting it is what makes the enum
  turnkey; a missing `lower.zig` arm is caught by the exhaustive switch.
- Numeric blobs stay byte-identical; the graph node table is unchanged.
