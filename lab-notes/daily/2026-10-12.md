# 2026-10-12 — Schema-driven Zig lowering: turnkey op surface for the comptime VM

Branch: `refactor/compiler-consolidation`

## Why

Adding or changing a VM op used to require editing the serializer
(`codegen/lower_zig.py`) in five places: append to the hand-written `Op` enum,
add a parallel f64 table (`gemm_alpha`, `layernorm_eps`, ...), thread that table's
dict through `_node_line` → `_graph_manifest` → both `_node_vm_info` call sites,
and add another branch to `_node_vm_info`'s if-ladder. That is mechanical, easy to
get wrong, and it is the only op surface with drift risk — the reason
`test_drift_guard_nodes_match_emitted_table` exists at all.

The goal of this refactor is **turnkey**: change a kernel and it works out of the
gate, with no hand-maintained serializer coupling. The lowering metadata now
lives next to the numpy oracle, declared once:

```python
@register_op("gemm", vm=VmOp(attrs=(AttrSpec("alpha", 1.0), AttrSpec("beta", 1.0)),
                             flags=("transB",)))
def _gemm(node, values, inputs): ...
```

`lower_zig` derives the enum, the baked `<op>_<attr>` tables, the packed `aux`
word, and the manifest from that registry. Adding a VM op now needs only a
`vm=VmOp(...)` (or nothing, for identity ops) plus a `lower.zig` switch arm — the
serializer is never touched. The `wire-linalg-kernel` skill drops from **six
surfaces to five**.

Framing note: `lower_zig` already emitted data (Zig-source-encoded constants),
never statements; this is an *encoding/ownership* change — the per-op encoding
knowledge moves from the serializer into a declarative schema — not a
"code → data" change.

## What changed

- **`codegen/vm_schema.py`** (new) — `VmOp` / `AttrSpec` dataclasses + registry.
  A `VmOp` declares: the Zig enum name (rename), `attrs` (f64 scalars → one
  `<op>_<attr>` table, shared index in `aux`), `flags` (bool attrs → `aux` bits),
  `array_attrs` (broadcast arrays → `clip`'s `lo`/`hi`), and `slot`
  (`attr:<name>` / `axis_code` / none). `vm_op_name`, `table_names`, and
  `get_vm_op` (identity default) are the accessors.
- **`codegen/ops.py`** — `register_op(name, *, vm: VmOp)` attaches the schema,
  and `vm` is **mandatory** (every one of the 48 registrations declares a
  `VmOp`, including the identity ops as `vm=VmOp()`). Annotated the 15 ops that
  previously had bespoke lowering: `const`/`input`/`output` (renames
  `cst`/`inp`/`out`), `where` (`where_op`), `clip` (array attrs),
  `slice`/`gather`/`concat` (`slot="attr:..."`), `min` (`axis_code`),
  `gemm`/`elu`/`leaky_relu`/`layernorm` (scalar attrs), `gru`/`mod` (flags). The
  serializer can no longer see an op without a schema — there is no identity
  default to fall back to.
- **Schema enforcement** — `register_op` rejects a handler with no `vm=`
  (`TypeError`); `vm_schema.get_vm_op` raises instead of defaulting;
  `vm_schema.missing_schemas()` lets `lower_zig` assert the registry is complete
  before emitting; and `TestVmSchema` covers all three (`declares_a_schema`,
  `requires_a_schema`, enum coverage). The schema set is now provably equal to
  the handler set.
- **`codegen/lower_zig.py`** — rewritten schema-driven. `_node_vm_info`,
  `_node_line`, and the five parallel-table passes are gone; a single
  `_encode_node` produces a `(vm_op, aux)` per node, consumed by both the emitted
  table and the manifest. The `Op` enum is derived from the registry
  (`_op_enum_names`). `const`/`input`/`output` keep a small structural block for
  the blob/input/port offsets (plumbing, not attributes). The two large numeric
  blobs and the f32-weight decision are unchanged.
- **`tests/test_codegen.py`** — new `TestVmSchema`: every registered op maps to a
  valid, non-reserved Zig variant; the renamed/attributed ops are declared; and
  the emitted enum covers every registered op (so an op can't silently drop out).
- **Docs** — `docs/codegen.md` module map + lower step; `runtime/README.md`
  serializer note; `.agents/skills/wire-linalg-kernel/SKILL.md` (six → five
  surfaces, schema step, pitfalls, worked example).

## Design decisions

- **Keep the Zig `Node` struct and ABI fixed.** The tempting alternative was to
  replace `aux` with generic `attrs`/`flags`/`slot` fields, but `lower.zig` arms,
  the frozen fixture graphs (`runtime/tests/graphs/*.zig` each re-declare `Node`
  exactly), and the C-ABI all depend on the current record. Encoding the schema
  into the *existing* `aux` + per-op table names (`aux = (index << nflags) |
  flagbits` for attrs+flags; `aux = flagbits` for flags-only; `aux = slot` for
  selectors) keeps the whole runtime, all fixtures, and the drift guard untouched
  — the refactor is Python-only.
- **`aux` packing is byte-for-byte the old scheme** (`gemm`: `(idx<<1)|transB`,
  read as `[aux/2]`), so node encodings reproduce exactly and the manifest is
  semantically identical.
- **Enum is derived, not hand-listed.** Order changes (register order vs. the old
  hand order) but Zig references variants by name and the drift guard parses
  nodes, not the enum, so this is cosmetic. Accepting it is what makes the enum
  turnkey; a missing `lower.zig` arm is caught by the exhaustive switch.
- Numeric blobs stay byte-identical; the graph node table is unchanged.

## Follow-up — module reorganization (same day, separate commit)

`shinro.codegen` had grown into one package doing four unrelated jobs. It is now
split by responsibility along a clean dependency DAG (core ← verification ←
scenarios ← cli):

- **`shinro.codegen`** (core, unchanged home): tracer/graph IR → compose →
  interpret → lower — `tracing`, `trace_backend`, `trace_node`,
  `infer_contract`, `ops`, `vm_schema`, `compose`, `interpreter`, `onnx_import`,
  `lower_zig`, `build`, plus `runtime_paths` and `measure` (the size metric stays
  with the codegen core it instruments).
- **`shinro.verification`**: `oracle`, `gate_a`, `stamp`, `verify`.
- **`shinro.scenarios`**: `gen` (was `scenario_gen`), `build` (was
  `scenario_build`), `recipes`, `bake`.
- **`shinro.cli`**: package (was the `shinro/cli.py` module) with `compile`
  (was `codegen/cli`), `components` (was `codegen/component_cli`), and
  `__main__` so `python -m shinro.cli` keeps working.

All moves used `git mv` (history preserved); imports rewritten **clean-break**
(no compatibility shims) across `src/`, `tests/`, `demos/`, `scripts/`;
`shinro-compile` repointed to `shinro.cli.compile:main`; the `docs/codegen.md`
module map and the `shinro` subpackage list updated.

Verification: `make test` 1941 passed / 5 skipped; `make lint` clean;
`python -m shinro.cli --help` and the `scripts/*.py` shims still resolve. No
behaviour changed — moved files are byte-identical apart from import paths.

## Follow-up — revive `demos/demo_codegen.py` (same day, separate commit)

`python -m demos.demo_codegen` crashed at Stage 2:

```text
ValueError: estimator mutated attribute 'P' during the traced call but
'state_P' was not pre-injected via trace_node(state_shapes=...); its recursion
would be silently frozen in the deployed graph. Add 'P' to state_shapes at the
trace site.
```

**Not a regression and never fixed.** The demo predates the recurrent-state
machinery: it was written 2026-08-24 (`736a970`) when a single-pass `trace_node`
with `state_shapes={"x_hat": ...}` was the norm, and it *deliberately* let the
KF covariance `P` bake at its trace-time value (`0.1*I`) — the verification loop
even reset numpy's `P` each trial to match the frozen constant, with a comment
saying so. On 2026-09-01 (`203964c`, "add recurrent state_P handling for KF")
`compose` gained the guard rail that rejects exactly that frozen recursion; the
demo was never updated. It was only relocated on 2026-09-21 (`d8c1d16`), so it
has been broken on `main` and `refactor/compiler-consolidation` alike since the
guard landed. `build._trace_with_state` (the two-pass discovery used by
`scenarios/recipes.build_base_graph`) was the framework's answer; the demo,
which calls `trace_node` directly, never adopted it.

**Fix** (demo-only; the guard rail is correct and unchanged):

- Pre-inject both recurrent KF attrs — `state_shapes={"x_hat": (n,), "P": (n, n)}`
  — at every KF trace site (Stages 1, 2, 4). `compose` now emits `state_P` as a
  real input port and a `state_P` output.
- Thread the composed graph's own `state_*` outputs back in each tick (4 ticks ×
  10 trials per stage) and run the live numpy loop alongside from the same
  `P0 = 0.1*I`; the covariance recursion is now exercised live on both sides.
- Drop the column `(n,1)` convention the demo still used (Stages 1, 2, 4): the
  framework moved to flat `(n,)` in `22f2750`, and the demo was the last
  holdout. Shapes are now `measurement (n_y,)`, `control_input (n_u,)`,
  `x_hat (n,)`, `P (n, n)` — matching `build._controller_input_shape`.
- Update the stale docstring/comments ("auto-reshape for (n,1) ↔ (n,)" is no
  longer needed; the "P was baked in" note is gone).

**Verification** — `python -m demos.demo_codegen`: all four stages PASS at
`max abs err = 0.00e+00` (Stage 1 interpret-vs-numpy; Stages 2/3/4 composed
KF/Luenberger + LQR over 4 ticks). `ruff check demos/demo_codegen.py` clean,
`py_compile` clean. Stage 2 composed ports now
`['y','x_ref','u_prev','state_x_hat','state_P'] → ['u']`, state
`['state_x_hat','state_P','u_prev']`.

No source change; demo + this note only.

## Follow-up — compile-time constant folding (same day, separate commit)

`shinro.codegen.optimize.fold_constants(cg)`, applied inside `lower_zig`
(default on; `lower_zig(cg, ..., fold=False)` escape hatch).

**Algorithm.** The composed graph is a pure dataflow DAG in execution order
(every node's inputs have smaller ids), so constant propagation is a *single
forward sweep* — no fixpoint. A node folds iff every input is constant and its
op is intrinsic. Folded values are computed with the **same `ops.py` numpy
handlers `interpret()` uses**, so the fold is **bit-exact**. Three compounding
transforms: const-fold, const dedup by `(shape, f64 bytes)`, and dead-node
elimination (roots = `input` + `output`; `input` nodes are kept even if unused
because the lowerer resolves port names by scanning the table).

**Non-foldable:** `input` (a port), `output` (a marker, rewired not folded),
`solve_qp` (solver-coupled). Because the fold lives *inside* lowering, the
`interpret()` oracle and gate A still run on the **unfolded** graph; the emitted
table + manifest describe the folded one.

**Node reduction** (fold-on vs composed): base KF+LQR 47→39, KF+MPC 49→41,
EKF CartPole 170→142 (`transpose`/`slice` collapsed), UKF CartPole 135→122,
SMC pendulum 140→113 (`add`/`div`/`reshape`/`transpose`/`slice` collapsed). Base
graph's win is mostly const dedup/DCE (14→6 consts); the estimator graphs also
get real forward folding of constant subexpressions.

**Measured cost** (cold ReleaseFast, cache cleared, fold-on vs fold-off):

| graph | nodes | .so | tick | .so fold-on vs fold-off diff |
|---|---|---|---|---|
| base KF+LQR | 47→39 | −0.56% | −0.1% | **0.0** |
| EKF CartPole | 170→142 | −1.76% | −2.5% | **0.0** |
| SMC pendulum | 140→113 | −1.25% | −0.6% | **0.0** |

Compile time is within noise (±10%, ordering-dependent). The decisive invariant:
the optimized `.so` is **bit-identical** to the unoptimized one (`max abs diff
0.000e+00`) — folding changes no arithmetic, only how much is baked. Wins are
largest where real compute folds (EKF's constant `transpose`/`slice`); the base
graph's win is const dedup/DCE. Confirms node count is not the dominant `.so`
cost once the solver + Zig runtime link.

**New** `tests/test_optimize.py` (8 tests): bit-exactness incl. transcendentals,
const dedup, shape-distinct non-merge, DCE, non-foldable ops, port-list
preservation, determinism. `fold_constants` re-exported from `shinro.codegen`.

**Verification:** `make test` **1949 passed / 5 skipped**; `make lint` clean;
`make zig-build` stamps + verifies; the base `.so` oracle passes against the
*unfolded* `interpret()` (bit-exact fold confirmed end to end).

**Out of scope (noted):** elementwise fusion — the earlier measurement flagged
it as the larger lever than node-count reduction.
