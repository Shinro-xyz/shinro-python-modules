### 2026-09-03 16:40 UTC — MPC_DeltaU .so: per-build graph/solver options + comptime n_vars check

Un-parked the last MPC deployment item: the MPC_DeltaU `.so`. Compose +
interpreter support for DeltaU already existed (tested at the interpreter
level since 2026-09-01); the blocker was the emosqp bake being one-per-`.so`
on a single shared path (`runtime/codegen/emosqp/`, n_vars=30 for
`mpc_lti_base.toml`), so a DeltaU bake (n_vars=45) couldn't coexist with the
shipped MPC_LTI one. This session made a second bake a first-class operation
instead of a clobber-and-restore dance, and closed the deferred comptime
graph↔bake check.

**Design decision (confirmed with the user):** generic `-Dgraph`/`-Dsolver_dir`
build options rather than the previously-deferred named per-scenario bundles
(`runtime/generated/<scenario>/`). Rationale: the options are the minimal
plumbing that makes any bake a build-time selection; named scenarios can layer
on top later if ever needed. The comptime n_vars check was included now (it
was the second deferred item).

**Changes:**

- `runtime/build.zig` — two new build options: `-Dgraph` (default
  `graph_data.zig`) and `-Dsolver_dir` (default `codegen/emosqp`). The graph
  and the bake's `solver_meta.zig` arrive in `lower.zig` as **anonymous
  imports** (`addAnonymousImport`), so a build can consume a graph/bake from
  any path (e.g. a pytest tmp dir) without touching the shared tree. The
  emosqp C sources are added via `addCSourceFile` (not `addCSourceFiles`,
  which rejects absolute paths) so an absolute `-Dsolver_dir` works. The
  Zig-side emosqp oracle test stays pinned to the shipped default bake (its
  oracle vectors are generated for that problem).
- `runtime/lower.zig` — `@import("graph_data.zig")` → `@import("graph_data")`
  (anonymous), plus `@import("solver_meta")` and a comptime assert in the
  `.solve_qp` case: node output size must equal `solver_meta.n_vars`, with a
  `@compileError` naming both sizes. A cross-config build now fails at compile
  time instead of silently linking a shape-mismatched solver.
- `scripts/gen_emosqp_test.py` — refactored into a callable `bake(config,
  out_dir, data_out)` + argparse wrapper (`--config`/`--out-dir`/`--data-out`,
  defaults preserve the shipped behavior). Emits `<out-dir>/solver_meta.zig`
  (`pub const n_vars`). The oracle sample state is now sized to the
  controller's input dim (`F.shape[0]` — 3 for MPC_LTI, 6 for DeltaU's
  augmented state), fixing a latent bug the DeltaU bake exposed.
- `scripts/gen_mpc.py` — `build_mpc_composed_graph(controller_config=...)`
  defaults to `mpc_lti_base.toml`; trace shapes are derived from the
  controller's `compute()` signature so DeltaU's `u_prev` input is traced
  without special-casing.
- `tests/test_zig_lowering.py` — `_build_so` gained `graph_path`/`solver_dir`
  params; new session fixtures `deltau_bake` (bakes `mpc_base.toml` into a
  tmp dir — never touches the shared tree) and `mpc_deltau_composed_so`
  (builds the KF+DeltaU graph against it). New tests:
  - `TestMpcDeltaUComposedOracle::test_so_matches_live_kf_mpc_deltau` —
    100-tick `.so` vs live numpy KF+DeltaU loop, `u_prev` threaded on both
    sides; asserts `< 1e-4` (same EMOSQP warm-start asymmetry rationale as
    the MPC_LTI oracle).
  - `test_comptime_n_vars_mismatch_rejects_build` — the DeltaU graph built
    against the shipped n_vars=30 bake must fail with the `@compileError`
    naming both sizes.
- Docs: `runtime/README.md` (new "Building a different graph/solver pair"
  section + the comptime check), `docs/codegen.md`, Makefile zig-section
  comment, `gen_mpc.py` docstring.

**Verification:**

- `make test-zig` green end-to-end (zig-gen → zig-build → zig test → 10
  pytest oracle tests, including the new DeltaU composed oracle and the
  comptime-mismatch rejection).
- Full suite: **946 passed, 5 skipped, 72 deselected**; ruff clean on all
  touched files.
- Manual cross-check: DeltaU `.so` vs interpreter max err ~1e-5 over 10
  random inputs (within OSQP tolerance, same as MPC_LTI).

**Deliberately unchanged:** the shipped default (KF+LQR graph +
`mpc_lti_base.toml` bake) is byte-identical — the bake script's defaults
preserve it, and the 4 timestamp-only diffs from re-running the bake were

**Remaining parked:** MPPI traceability, SMC's dynamics-term wiring, the C

### 2026-09-03 21:30 UTC — build manifest: the audit trail for every binary

Follow-up to the DeltaU `.so` slice: every build now emits a **deterministic
report** next to the artifact plus a **timestamped archive copy**, so teams
can see what a binary contains (ops-wise) and browse which controller
combinations were built and when.

**Design (confirmed with the user):** the report's core is the *compiled
content* of the `.so` — the op histogram and port layout of the node table the
VM executes — not just provenance metadata. Timestamps live in the archive
**filename only**, never in the report, so the report is a pure function of
its inputs: identical inputs ⇒ byte-identical report. The archive (timestamped
copies under `<prefix>/manifests/`) provides the "what did we try, when"
history; the deterministic report provides the "is this the same binary"
byte-compare. "The LQR we had two weeks ago" = git checkout / re-bake → rebuild
→ report byte-matches the archived one.

**Changes:**

- `src/shinro/codegen/lower_zig.py` — writes `<stem>_manifest.json` next to
  `graph_data.zig`, derived from the same node table it serializes:
  `nodes_total`, `op_histogram`, `ops`, `buf_len`, `const_blob_len`, the C-ABI
  port layout (inputs/outputs/state + shapes), `solve_qp.expected_n_vars`, and
  `float_type`. `json.dump(sort_keys=True)` → deterministic bytes.
- `runtime/build.zig` — `writeManifest()` runs after every build: reads the
  graph manifest (raw-embedded — it's already valid JSON), parses
  `solver_meta.zig` (now carries `n_vars`, `n_cons`, `eps`, `config`), hashes
  `graph_data.zig` + bake `workspace.c` (sha256), and writes
  `<prefix>/lib/libbase.manifest.json` + `<prefix>/manifests/<UTC>-<sha8>.json`.
  Report fields: target triple, optimize mode, zig version, libc, float_type,
  provenance (paths + hashes), solver facts, graph content. Hand-built JSON
  (no std.json — 0.16's API is a big departure); file I/O via the new
  `std.Io.Dir` API (`b.graph.io`), timestamp via `posix.system.clock_gettime`.
- `scripts/gen_emosqp_test.py` — `solver_meta.zig` gains `n_cons`, `eps`,
  `config` (provenance surfaced in the report).
- `tests/test_zig_lowering.py` — new `TestBuildManifest` (module fixture
  builds base + DeltaU `.so`s): report exists with correct build/solver/graph
  fields; op histogram matches the composed graph; DeltaU vs base differ
  op-wise (`solve_qp`/`slice` present, n_vars pair 45/45); archive copy is
  timestamped and byte-identical to the report; drift guard — `nodes_total`
  cross-checked against the `.`-op entries in `graph_data.zig`.
- Docs: `runtime/README.md` ("Build manifest — the audit trail" section),
  `docs/codegen.md` (manifest paragraph).

**Verification:**

- `make test-zig` green: 14 pytest oracle tests (10 prior + 4 manifest).
- Determinism proven: two identical builds produce byte-identical reports
  (`diff` clean); only the archive filename differs.
- DeltaU report shows `solve_qp: {expected_n_vars: 45}` matching the bake's
  `n_vars: 45`; base report shows `solve_qp: null`.
- Full suite: **950 passed, 5 skipped, 72 deselected**; ruff clean.

**Deliberately unchanged:** the shipped default artifacts are byte-identical
(the bake's 4 timestamp-only diffs reverted again); the report is
timestamp-free for reproducibility. **Deferred:** in-binary
`shinro_manifest()` getter (runtime introspection of the report), committed
manifests as a repo convention.

### 2026-09-03 22:30 UTC — manifest v2: node table (dual names) + ASCII flowchart

The user wanted the manifest to describe the *graph itself*, not just the
aggregate histogram and ports — and liked the idea of a human-readable ASCII
flowchart on top of the structured JSON.

**Changes:**

- `lower_zig.py` — extracted the Python→Zig op/aux mapping into a single
  source of truth `_node_vm_info()` (shared by the emitted table and the
  manifest), and extended `_graph_manifest` with two new fields:
  - **`nodes`** — the ordered node list: `{i, op (Python), vm_op (Zig),
    inputs (wiring), rows, cols, offset (buffer start), aux}`. Const *values*
    deliberately excluded (pinned by `provenance.graph_sha256`); structure
    lives in the manifest, data in the hash.
  - **`flowchart`** — one line per node in execution order:
    `idx  vm_op (py_op)  shape  <- producers  buf[a..b]  aux-detail`, with
    per-op annotations (`in[..] port N`, `blob[..]`, `clip[..]`,
    `-> out[..] port u`, `-> state[..]`, `from[..]` for slice). The
    dual-vocabulary naming the user chose (py name omitted when identical);
    `buf[a..b]` is the memory layout (`offsets`), `aux` the per-op data
    pointer — the two different "where does this node live" concepts.
- `tests/test_zig_lowering.py` — drift guard **upgraded from count-only to
  node-by-node**: a regex parser extracts every `.{ .op = .X, .inputs = ...,
  .rows, .cols, .aux }` entry from `graph_data.zig` and compares vm_op,
  wiring, shape, and aux field-for-field against the manifest `nodes` list.
  New tests: `nodes` schema + cumulative-offset contiguity, DeltaU node-list
  wiring (solve_qp ← q matmul, 45×1), flowchart header/line-count/markers for
  base and DeltaU, and lowering determinism (two lowers → byte-identical
  manifests).
- Docs: `runtime/README.md` (flowchart example block in the manifest section),
  `docs/codegen.md` (one sentence).

**Verification:** `make test-zig` green — 17 pytest oracle tests; ruff clean
on all touched files.

**Deferred (unchanged):** in-binary `shinro_manifest()` getter; committed
manifests as a repo convention.

  (`test_flowchart_renders_graph`, `test_flowchart_deltau_marks_solve`); the
  node-list drift guard (field-for-field vs `graph_data.zig`) and determinism
  tests stay.
- Docs: `runtime/README.md` (flowchart block → node-list description),
  `docs/codegen.md` (sentence updated); `runtime/graph_data_manifest.json`
  regenerated.

**Verification:** `make test-zig` green — 15 oracle tests; full suite
**953 passed, 5 skipped, 72 deselected**; ruff clean.

The manifest now stays lean: structure in `nodes` (dual names), data pinned by
`provenance.graph_sha256` — no redundant renderings.
