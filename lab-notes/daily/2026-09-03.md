# Lab Notes — 2026-09-03

### 2026-09-03 16:40 UTC — MPC_DeltaU .so: per-build graph/solver options + comptime n_vars check

Un-parked the last MPC deployment item: the MPC_DeltaU `.so`. Compose +
interpreter support for DeltaU already existed (tested at the interpreter
level since 2026-09-01); the blocker was the emosqp bake being one-per-`.so`
on a single shared path (`runtime/codegen/emosqp/`, n_vars=30 for
`mpc_lti_base.toml`), so a DeltaU bake (n_vars=45) couldn't coexist with the
shipped MPC_LTI one. This session made a second bake a first-class operation
instead of a clobber-and-restore dance, and closed the deferred comptime
graph↔bake check.

**Design decision (confirmed with the user):** generic `-Dgraph`/`-Dsolver_dir`
build options rather than the previously-deferred named per-scenario bundles
(`runtime/generated/<scenario>/`). Rationale: the options are the minimal
plumbing that makes any bake a build-time selection; named scenarios can layer
on top later if ever needed. The comptime n_vars check was included now (it
was the second deferred item).

**Changes:**

- `runtime/build.zig` — two new build options: `-Dgraph` (default
  `graph_data.zig`) and `-Dsolver_dir` (default `codegen/emosqp`). The graph
  and the bake's `solver_meta.zig` arrive in `lower.zig` as **anonymous
  imports** (`addAnonymousImport`), so a build can consume a graph/bake from
  any path (e.g. a pytest tmp dir) without touching the shared tree. The
  emosqp C sources are added via `addCSourceFile` (not `addCSourceFiles`,
  which rejects absolute paths) so an absolute `-Dsolver_dir` works. The
  Zig-side emosqp oracle test stays pinned to the shipped default bake (its
  oracle vectors are generated for that problem).
- `runtime/lower.zig` — `@import("graph_data.zig")` → `@import("graph_data")`
  (anonymous), plus `@import("solver_meta")` and a comptime assert in the
  `.solve_qp` case: node output size must equal `solver_meta.n_vars`, with a
  `@compileError` naming both sizes. A cross-config build now fails at compile
  time instead of silently linking a shape-mismatched solver.
- `scripts/gen_emosqp_test.py` — refactored into a callable `bake(config,
  out_dir, data_out)` + argparse wrapper (`--config`/`--out-dir`/`--data-out`,
  defaults preserve the shipped behavior). Emits `<out-dir>/solver_meta.zig`
  (`pub const n_vars`). The oracle sample state is now sized to the
  controller's input dim (`F.shape[0]` — 3 for MPC_LTI, 6 for DeltaU's
  augmented state), fixing a latent bug the DeltaU bake exposed.
- `scripts/gen_mpc.py` — `build_mpc_composed_graph(controller_config=...)`
  defaults to `mpc_lti_base.toml`; trace shapes are derived from the
  controller's `compute()` signature so DeltaU's `u_prev` input is traced
  without special-casing.
- `tests/test_zig_lowering.py` — `_build_so` gained `graph_path`/`solver_dir`
  params; new session fixtures `deltau_bake` (bakes `mpc_base.toml` into a
  tmp dir — never touches the shared tree) and `mpc_deltau_composed_so`
  (builds the KF+DeltaU graph against it). New tests:
  - `TestMpcDeltaUComposedOracle::test_so_matches_live_kf_mpc_deltau` —
    100-tick `.so` vs live numpy KF+DeltaU loop, `u_prev` threaded on both
    sides; asserts `< 1e-4` (same EMOSQP warm-start asymmetry rationale as
    the MPC_LTI oracle).
  - `test_comptime_n_vars_mismatch_rejects_build` — the DeltaU graph built
    against the shipped n_vars=30 bake must fail with the `@compileError`
    naming both sizes.
- Docs: `runtime/README.md` (new "Building a different graph/solver pair"
  section + the comptime check), `docs/codegen.md`, Makefile zig-section
  comment, `gen_mpc.py` docstring.

**Verification:**

  pytest oracle tests, including the new DeltaU composed oracle and the
  comptime-mismatch rejection).
- Full suite: **946 passed, 5 skipped, 72 deselected**; ruff clean on all

- Manual cross-check: DeltaU `.so` vs interpreter max err ~1e-5 over 10

**Deliberately unchanged:** the shipped default (KF+LQR graph +
`mpc_lti_base.toml` bake) is byte-identical — the bake script's defaults
preserve it, and the 4 timestamp-only diffs from re-running the bake were
reverted. The `.so` stays stateless; the host owns state packing and seeding.

**Remaining parked:** MPPI traceability, SMC's dynamics-term wiring, the C
